RL tour · Chapter 10 of 11

Policy gradients on language models

A language model that writes an answer is a policy that picks one token at a time. This chapter carries chapter 5's policy gradient over to that setting. It derives the two baselines that recent reasoning-model papers use in place of a critic, RLOO and GRPO, and measures what each one does to the noise and the direction of the gradient.

1. From game decisions to tokens

Chapters 1 to 8 trained one agent, Spire Mentor's Instinct, on one game. A run lasts about 667 decisions, and each decision offers about seven legal options. Rewards arrive along the way: 0.002 for each floor climbed, 0.05 for each of the three bosses that pay out and 1 for a win (chapter 3). A critic learns the value of each state (chapter 4), and PPO turns the critic's advantages into a weight update (chapter 5).

Reinforcement learning on a language model uses the same policy gradient theorem, but almost every quantity in it changes size. The agent picks a token from its whole vocabulary at every step, and an episode is one answer to one prompt. The reward usually arrives once, when a program checks the finished answer, and the environment is often only a list of prompts with known answers.

Those differences explain the design choices in recent papers. Most of them drop the critic and instead sample several answers to the same prompt, using the other answers' rewards as the baseline. This chapter derives those estimators from chapter 5, measures their noise on a toy problem, and goes through the problems that later papers found with them.

Chapter 9 covers sample efficiency in general, and chapter 11 covers environments for language-model agents: how verifiers are built, and how a policy learns to exploit a weak one. This chapter touches those topics only where the gradient depends on them.

2. Text generation as a decision process

Chapter 1 defined a decision process by its states, actions, transitions, rewards and the end of an episode. Here is each part for a model that answers one prompt.

  • State. The first state is the prompt, \(s_0 = x\). After \(t\) tokens the state is \(s_t = (x, y_{\lt t})\), the prompt followed by everything written so far.
  • Action. One token \(y_t\). The legal action set \(\mathcal{A}(s)\) is the whole vocabulary, the same at every state.
  • Transition. Append the token. Nothing random happens, so \(s_{t+1} = (x, y_{\le t})\).
  • End of the episode. The model writes the end-of-sequence token, EOS, or reaches the length budget.
  • Reward. Zero after every token, then \(v(x, y)\) once the completion ends. The discount is \(\gamma = 1\).
  • Start state. A prompt drawn from the dataset \(\mathcal{D}\).

The policy is the language model itself. Its last layer gives one logit per vocabulary entry, and a softmax turns the logits into \(\pi_\theta(y_t \mid x, y_{\lt t})\). That is the same construction as Instinct's softmax over legal options in chapter 2, except that the action set is far larger and never changes. Liu et al. write down the same decision process for reasoning models [6]. The next three figures add one part of it at a time.

Two features of this process are unusual next to Spire Mentor. First, the transition is deterministic and known, so the state is exactly the history of actions. Ahmadian et al. point out that you can therefore treat the whole completion as one action and the problem as a contextual bandit, with the prompt as the context [4]. Second, every token before the end earns zero reward, and Section 3 shows what that does to the gradient.

Agent trajectories

An agent that calls tools writes some tokens and reads others. The model writes a tool call, the environment runs it and appends the result to the context, and the model reads the result and writes again. The tool's output becomes part of the state, but the policy did not sample it, so it is not an action. The log-probability of the trajectory therefore sums only over the tokens the model wrote, and the loss masks out every token the environment wrote.

Compared with a single completion, two things change. The transition is no longer deterministic, because a tool can return different results. The episode can also be long, with many model turns, which brings back the credit-assignment problem that Spire Mentor's critic exists to solve. The rest of this chapter uses single completions, because the published methods were developed on them.

3. The policy gradient for a completion

The probability of a completion is a product of next-token probabilities. Taking the log turns the product into a sum:

\begin{equation} \log \pi_\theta(y \mid x) = \sum_{t=0}^{\lvert y\rvert - 1} \log \pi_\theta\big(y_t \mid x, y_{\lt t}\big). \label{eq:seqlogp} \end{equation}

Compare it with chapter 5's trajectory log-probability. There, \(\log p_\theta(\tau)\) also held the start-state term and one transition term per step. Neither depends on \(\theta\), so both dropped out of the gradient. Here the start-state term is \(\log \mathcal{D}(x)\) and every transition has probability 1, so Equation \eqref{eq:seqlogp} is all that remains.

The objective is the expected reward over prompts and completions:

\begin{equation} J(\theta) = \mathbb{E}_{x \sim \mathcal{D}}\, \mathbb{E}_{y \sim \pi_\theta(\cdot \mid x)}\big[ v(x, y) \big]. \label{eq:J} \end{equation}

We take the gradient the way chapter 5 did. For one prompt, write the inner expectation as a sum over completions and use \(\nabla \pi = \pi\, \nabla \log \pi\):

\begin{equation} \nabla_\theta J(\theta) = \mathbb{E}_{x}\, \mathbb{E}_{y \sim \pi_\theta}\big[ v(x, y)\, \nabla_\theta \log \pi_\theta(y \mid x) \big] = \mathbb{E}_{x}\, \mathbb{E}_{y}\Big[ \sum_{t} \nabla_\theta \log \pi_\theta(y_t \mid x, y_{\lt t})\; v(x, y) \Big]. \label{eq:seqpg} \end{equation}

The second form is chapter 5's per-step theorem with every step's weight equal to \(v(x,y)\). In chapter 5 the weight on step \(t\) was the return from that step, \(G_t = \sum_{k \ge t} r_k\). Here all reward sits at the end and \(\gamma = 1\), so \(G_t = v(x, y)\) for every \(t\). Every token in a completion gets the same weight. Within one completion, the estimator cannot tell a decisive token from filler. It learns which tokens matter only by averaging over many completions, in which a token that tends to appear in correct answers collects more positive weight than one that does not.

With a reward of 0 or 1, the inner expectation is the success rate, \(\mathbb{E}_y[v(x,y)] = p_x\). So the gradient for one prompt is the gradient of its success rate:

\begin{equation} \nabla_\theta\, p_x = \mathbb{E}_{y \sim \pi_\theta(\cdot\mid x)}\big[ v(x,y)\, \nabla_\theta \log \pi_\theta(y \mid x) \big]. \label{eq:px} \end{equation}

Without a baseline, this is fine-tuning on correct answers

Estimate Equation \eqref{eq:px} with \(n\) samples and no baseline. Wrong answers have \(v = 0\) and drop out. What remains is \(\frac{1}{n}\sum_{i:\,R_i = 1} \nabla_\theta \log \pi_\theta(y^{(i)} \mid x)\), the gradient of the log-likelihood of the correct samples. That is supervised fine-tuning on the model's own correct answers, drawn fresh from the current policy. DeepSeekMath calls this Online RFT and writes its gradient coefficient as 1 for a correct sample and 0 for a wrong one [1].

Worked example · one prompt, four samples

The prompt is "What is 17 × 24?". The policy answers correctly a quarter of the time, so \(p_x = 0.25\). You sample four completions: one says 408 and three give wrong numbers. Without a baseline, the estimate raises the log-probability of the one correct completion with weight \(\frac{1}{4}\) and does nothing with the three wrong ones. If none of the four had been correct, the estimate would be zero.

The estimate is unbiased, but most of its information comes from whether a correct sample happened to appear. A baseline lets the wrong answers carry information too.

4. RLVR: rewards from a verifier

Definition 10.1 · RLVR

Reinforcement learning with verifiable rewards (RLVR) trains a language model on prompts whose answers a program can check. The reward is the program's output. Lambert et al. introduced the term in the Tülu 3 report [5, §6], with the objective

\begin{equation} \max_\theta\; \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_\theta(\cdot\mid x)}\Big[ v(x, y) - \beta_{\mathrm{KL}}\, D_{\mathrm{KL}}\big( \pi_\theta(\cdot \mid x) \,\big\|\, \pi_{\mathrm{ref}}(\cdot \mid x) \big) \Big]. \label{eq:rlvr} \end{equation}

In Tülu 3, \(v(x,y)\) is 10 when the answer is correct and 0 otherwise.

A verifier is a function of the prompt and the completion that a program computes without learned parameters. Tülu 3 uses three kinds. For GSM8K and MATH problems, it extracts the final answer and checks for an exact match with the reference. For instruction-following prompts, it checks the stated constraints, such as a word count or a required format. The training set held about 30,000 prompts: 7,473 from GSM8K, 7,500 from MATH and 14,973 instruction-following prompts. The authors set the reward of 10 after pilot experiments and did not tune it further [5].

Tülu 3 trained RLVR with PPO and a value model, which it initialised from a general reward model. The report places RLVR next to earlier methods that also learn from checked answers, such as STaR, TRICE and VinePPO. VinePPO had already used binary correctness rewards for math inside a PPO-based method. Tülu 3 named the approach, ran it fully online in a standard PPO loop, and extended it beyond math to instruction-following constraints [5].

A learned reward model is not a verifier. Classic RLHF trains a reward model on human preferences and lets the policy optimise against it. For reasoning tasks, the DeepSeek-R1 authors used rule-based rewards for accuracy and format, and they say they avoided neural reward models because the policy can learn to exploit them [2]. Chapter 11 covers what makes a verifier hard to exploit.

For the gradient, RLVR changes two things. The reward takes only a few values, usually two, so one number \(p_x\) summarises the whole reward distribution for a prompt. The reward also has no measurement noise, so all the variance in Equation \eqref{eq:px} comes from sampling the completions.

5. Baselines without a critic

Chapter 5 showed that any baseline that does not depend on the action leaves the gradient unbiased. Here the action is the whole completion. For any \(b(x)\) that does not depend on \(y\),

\begin{equation} \mathbb{E}_{y \sim \pi_\theta(\cdot\mid x)}\big[ b(x)\, \nabla_\theta \log \pi_\theta(y \mid x) \big] = b(x)\, \nabla_\theta \sum_y \pi_\theta(y \mid x) = b(x)\, \nabla_\theta 1 = 0. \label{eq:bzero} \end{equation}

The natural baseline is the prompt's value, \(V^\pi(x) = p_x\). Chapter 4 would learn it with a critic. With a prompt dataset there is a cheaper option: sample \(n\) completions for the same prompt, and build each one's baseline from the others.

RLOO: the leave-one-out baseline

The leave-one-out baseline gives each of several samples the mean reward of the others. Kool, van Hoof and Welling stated it for REINFORCE with multiple samples and applied it to sampled sequences. Their later paper credits the idea of a baseline built from the other samples to VIMCO [3, 11, Eq. 23]. Ahmadian et al. brought it to language-model training under the name RLOO, REINFORCE leave-one-out [4, §2.3]. Draw \(y^{(1)}, \dots, y^{(n)}\) independently from \(\pi_\theta(\cdot\mid x)\), and give each completion the mean reward of the other \(n-1\) as its baseline:

\begin{equation} \hat g_{\mathrm{RLOO}} = \frac{1}{n} \sum_{i=1}^{n} \Big( R_i - \frac{1}{n-1} \sum_{j \ne i} R_j \Big)\, \nabla_\theta \log \pi_\theta\big(y^{(i)} \mid x\big). \label{eq:rloo} \end{equation}

We show it is unbiased. Call the baseline of sample \(i\) \(b_i\). It depends only on the other samples, \(y^{(j)}\) for \(j \ne i\). The samples are independent given \(x\), so \(b_i\) is independent of \(y^{(i)}\), and the expectation of the product splits:

\begin{equation} \mathbb{E}\big[ b_i\, \nabla_\theta \log \pi_\theta(y^{(i)} \mid x) \big] = \mathbb{E}[b_i]\; \mathbb{E}\big[ \nabla_\theta \log \pi_\theta(y^{(i)} \mid x) \big] = \mathbb{E}[b_i] \cdot 0 = 0. \label{eq:loo-unbiased} \end{equation}

The second factor is zero by Equation \eqref{eq:bzero} with \(b = 1\). Only the \(R_i\) term of each weight is left, and each of the \(n\) samples contributes \(\nabla_\theta\, p_x\) by Equation \eqref{eq:px}. So \(\mathbb{E}[\hat g_{\mathrm{RLOO}}] = \nabla_\theta\, p_x\) exactly, for any \(n \ge 2\).

The weight on sample \(i\) can also be written with the group mean \(\bar R = \frac{1}{n}\sum_j R_j\). Since \(\sum_{j\ne i} R_j = n\bar R - R_i\), we get \(R_i - b_i = \frac{n}{n-1}(R_i - \bar R)\), and

\begin{equation} \hat g_{\mathrm{RLOO}} = \frac{1}{n-1} \sum_{i=1}^{n} \big( R_i - \bar R \big)\, \nabla_\theta \log \pi_\theta\big(y^{(i)} \mid x\big). \label{eq:rloo-mean} \end{equation}

The authors' poster gives both forms [3]. Equation \eqref{eq:rloo-mean} shows what goes wrong if you subtract the group mean and divide by \(n\) instead of \(n-1\). That estimator is \(\frac{n-1}{n}\,\hat g_{\mathrm{RLOO}}\), so its expectation is \(\frac{n-1}{n}\nabla_\theta\, p_x\). The direction is right and the scale is short by a factor that depends only on \(n\): one half at \(n = 2\), and 0.94 at \(n = 16\). Liu et al. state the same relation between the two [6, App. A].

Go back to the worked example and draw 16 samples instead of 4, one of them correct. RLOO gives the correct completion a weight of \(1 - 0 = 1\). Each wrong completion's baseline is \(\frac{1}{15}\), so each gets a weight of \(-\frac{1}{15} \approx -0.067\). Each wrong answer now lowers its own probability by a small amount.

GRPO: group-normalised advantages

Shao et al. introduced Group Relative Policy Optimization (GRPO) in the DeepSeekMath paper [1], and the DeepSeek-R1 paper used it to train DeepSeek-R1-Zero and DeepSeek-R1 [2]. GRPO keeps PPO's clipped loss from chapter 5 and replaces the critic with a group statistic. The next three figures go through one GRPO step.

GRPO's advantage for completion \(i\) is its reward standardised within the group [1, §4.1.2]:

\begin{equation} \hat A_{i} = \frac{R_i - \bar R}{s_R}, \qquad s_R = \operatorname{std}(R_1, \dots, R_n), \label{eq:grpo-adv} \end{equation}

and the objective, in this tour's symbols, is

\begin{equation} \begin{aligned} J_{\mathrm{GRPO}}(\theta) = \mathbb{E}\bigg[ \frac{1}{n}\sum_{i=1}^{n} \frac{1}{\lvert y^{(i)}\rvert} \sum_{t=0}^{\lvert y^{(i)}\rvert-1} \Big( &\min\big( \rho_{i,t}\, \hat A_i,\; \operatorname{clip}(\rho_{i,t}, 1-\epsilon, 1+\epsilon)\, \hat A_i \big) \\ &- \beta_{\mathrm{KL}}\, \hat D_{i,t} \Big) \bigg]. \end{aligned} \label{eq:grpo} \end{equation}

The ratio is \(\rho_{i,t} = \pi_\theta(y^{(i)}_t \mid x, y^{(i)}_{\lt t}) \,/\, \pi_{\mathrm{old}}(y^{(i)}_t \mid x, y^{(i)}_{\lt t})\), as in chapter 5. The expectation is over prompts \(x \sim \mathcal{D}\) and groups of completions drawn from \(\pi_{\mathrm{old}}\). The term \(\hat D_{i,t}\) is a per-token estimate of the KL divergence from \(\pi_\theta\) to \(\pi_{\mathrm{ref}}\). DeepSeekMath uses

\begin{equation} \hat D_{i,t} = \frac{\pi_{\mathrm{ref}}(y^{(i)}_t \mid \cdot)}{\pi_\theta(y^{(i)}_t \mid \cdot)} - \log \frac{\pi_{\mathrm{ref}}(y^{(i)}_t \mid \cdot)}{\pi_\theta(y^{(i)}_t \mid \cdot)} - 1, \label{eq:k3} \end{equation}

where the dot stands for the state \((x, y^{(i)}_{\lt t})\). The estimate is never negative because \(u - \log u - 1 \ge 0\) for every \(u > 0\), and its expectation under \(\pi_\theta\) is the KL divergence. DeepSeekMath adds the KL term to the loss. PPO set-ups for RLHF more often subtract a KL penalty from the reward, and the paper notes the difference [1].

Read against chapter 5, Equation \eqref{eq:grpo} is PPO's clipped surrogate with three changes. The advantage comes from Equation \eqref{eq:grpo-adv} instead of GAE. The loss averages over tokens within each completion and then over completions. A KL penalty to a frozen reference replaces the value loss in the combined objective. DeepSeekMath trained with 64 samples per question, a learning rate of \(10^{-6}\), \(\beta_{\mathrm{KL}} = 0.04\), a maximum length of 1,024 tokens and a batch of 1,024, and it took a single gradient step per batch of samples [1]. With one step, \(\pi_{\mathrm{old}} = \pi_\theta\) when the gradient is taken, every ratio is 1, and the clip has no effect. The paper's appendix notes that the min and the clip can be dropped in that case [1, App. A.1.5].

What the normalisation does to bias and scale

Equation \eqref{eq:grpo-adv} does two things, and they have different effects.

Subtracting the group mean gives the mean-centred estimator from the RLOO subsection. Its expectation is \(\frac{n-1}{n}\) times the true gradient, so the direction is unbiased and the scale is slightly short.

Dividing by \(s_R\) rescales each prompt's contribution by a factor that differs between prompts. To see the effect, replace the sample statistic by the quantity it estimates. For a reward of 0 or 1, the standard deviation is \(\sigma_x = \sqrt{p_x(1 - p_x)}\). With that oracle value in place of \(s_R\), and with \(n\) large enough that the \(\frac{n-1}{n}\) factor is close to 1, the expected contribution of prompt \(x\) is

\begin{equation} \mathbb{E}\big[ \hat A_i\, \nabla_\theta \log \pi_\theta(y^{(i)}\mid x) \big] \approx \frac{\nabla_\theta\, p_x}{\sqrt{p_x(1-p_x)}} = \nabla_\theta \Big( 2 \arcsin \sqrt{p_x} \Big). \label{eq:arcsin} \end{equation}

The last step is the chain rule. The derivative of \(2\arcsin\sqrt{p}\) with respect to \(p\) is \(1/\sqrt{p(1-p)}\). So under this idealisation, GRPO ascends \(\sum_x 2\arcsin\sqrt{p_x}\) instead of the success rate \(\sum_x p_x\). The derivation is this chapter's, not a result stated in the cited papers. It is an approximation, because the real \(s_R\) is estimated from the same samples it divides.

In Figure 10.8, the prompts that the policy almost always solves, or almost never solves, get the largest weight. Liu et al. call this the question-level difficulty bias [6], and Equation \eqref{eq:arcsin} states it as a change of objective. Whether you want that change depends on the prompts. Upweighting rare successes on hard prompts can help a model learn them. Upweighting prompts it already solves 97% of the time spends gradient on little expected gain.

A finite group adds two more effects. When every completion in a group gets the same reward, \(s_R = 0\) and the advantages are \(0/0\). Implementations add a small constant to the denominator, so the group contributes zero gradient. The second effect is that at \(n = 2\), with the population standard deviation, GRPO is exactly RLOO. The only informative group is one correct and one wrong, where \(\bar R = 0.5\), \(s_R = 0.5\) and the advantages are \(\pm 1\). RLOO gives \(1 - 0 = 1\) and \(0 - 1 = -1\). The cited papers do not say whether \(s_R\) uses the population or the sample standard deviation, so this identity is unverified for any specific implementation. With the sample standard deviation the advantages at \(n = 2\) are \(\pm 0.71\) instead.

Worked example · the same groups under RLOO and GRPO

Take a group of 16 with one correct completion. Then \(\bar R = \frac{1}{16}\) and \(s_R = \sqrt{15}/16 \approx 0.242\), using the population standard deviation as in Section 9's toy. GRPO gives the correct completion an advantage of \(0.9375 / 0.242 \approx +3.87\) and each wrong one \(-0.0625/0.242 \approx -0.258\). RLOO gave \(+1\) and \(-0.067\).

Now take a group of 16 with eight correct. GRPO gives \(\pm 1\). RLOO gives \(1 - \frac{7}{15} \approx +0.53\) and \(0 - \frac{8}{15} \approx -0.53\).

Relative to RLOO, GRPO multiplies the first group by 3.87 and the second by 1.88, so, measured against the group with eight correct, the rare success counts about twice as much under GRPO as under RLOO.

Why the critic went away

DeepSeekMath gives two reasons for dropping the critic [1]. PPO's value model is usually another model of size comparable to the policy, which costs memory and compute. The reward also arrives only at the last token, which makes a value for every token hard to train. The DeepSeek-R1 paper repeats the second point, saying that a value model is hard to train when only the outcome reward is available, especially for long chains of thought in which the model revises earlier steps [2, App. A.3].

The critic is not required by RLVR. Tülu 3 trained with PPO and a value model [5]. Without one, you give up a baseline for each token. The group baseline is one number per prompt, and every token in a completion gets the same advantage. A token-level critic would estimate, for each prefix, the probability that the completion ends correct, and the advantage of a token would be the change in that estimate. Section 8 explains why Spire Mentor keeps its critic.

6. Known problems and their fixes

After DeepSeek-R1, several groups examined GRPO's details and found problems. This section covers six of them.

Length bias from the per-completion average

Equation \eqref{eq:grpo} divides each completion's token sum by its own length \(\lvert y^{(i)}\rvert\), so a token's share of the gradient depends on the length of its completion. Libraries aggregate the per-token loss \(\ell_{i,t}\) in at least three ways:

\begin{equation} \underbrace{\frac{1}{n}\sum_{i} \frac{1}{\lvert y^{(i)}\rvert} \sum_{t} \ell_{i,t}}_{\text{per completion (GRPO)}}, \qquad \underbrace{\frac{1}{\sum_i \lvert y^{(i)}\rvert} \sum_{i}\sum_{t} \ell_{i,t}}_{\text{per token (DAPO)}}, \qquad \underbrace{\frac{1}{n L} \sum_{i}\sum_{t} \ell_{i,t}}_{\text{constant (Dr. GRPO)}}. \label{eq:agg} \end{equation}

In the third form, \(L\) is a constant that does not depend on the batch, such as the generation budget. Trace two wrong completions with the same advantage, \(-0.5\), one 100 tokens long and one 1,000 tokens long. Under the per-completion average, each token of the short one gets a weight of \(-0.005\) and each token of the long one \(-0.0005\), so each token of the long wrong answer is pushed down ten times less. Among correct answers, the same rule gives each token of a short answer the larger push up.

Liu et al. call this the response-level length bias [6]. They report that under GRPO the length of incorrect responses keeps growing during training, and that their fix, Dr. GRPO, removes the growth. Dr. GRPO drops both the per-completion length and the standard deviation from Equation \eqref{eq:grpo} and divides by a constant instead. Their Table 2 lists open-source PPO implementations whose losses normalise by response length. Their Listing 1 gives OpenRLHF as an example that divides each completion by its own length, and trl and verl as examples that divide by the number of tokens in the batch. DAPO uses the per-token average, which gives every token in the batch the same weight [7]. Lambert's RLHF book compares the aggregation choices in a section of its own [10].

Difficulty bias from the standard deviation

Section 5 derived this bias. Dr. GRPO removes the division by \(s_R\), which leaves the mean-centred estimator, unbiased in direction and short by \(\frac{n-1}{n}\) in scale. Liu et al. report that removing each of the two normalisations on its own already improves on GRPO in their experiments [6].

Groups that carry no signal

If every completion in a group gets the same reward, all advantages are zero and the group adds nothing to the gradient. For a reward of 0 or 1, the probability of that event is

\begin{equation} P(\text{all } n \text{ rewards equal}) = p_x^{\,n} + (1 - p_x)^{n}. \label{eq:allsame} \end{equation}

A prompt at \(p_x = 0.9\) is wasted 82% of the time at \(n = 2\), 66% at \(n = 4\), 43% at \(n = 8\) and 19% at \(n = 16\). As training succeeds, more prompts move toward \(p_x = 1\), and more of each batch is wasted. DAPO's dynamic sampling keeps sampling and drops every group whose accuracy is 0 or 1 until the batch is full of groups with nonzero advantages [7]. The cost is the generation compute spent on the dropped groups.

Entropy collapse

Chapter 2 defined the entropy of the policy as a measure of how much it still explores, and chapter 5 added it to the loss as a bonus. Under GRPO on language models, entropy falls fast. Cui et al. measured it across many training runs [8]. In their runs, 73% of the entropy drop and 76% of the performance gain happened in the first 200 of 2,400 steps. They fit performance against entropy with \(\text{performance} = -a\, e^{\mathcal{H}} + b\), so once entropy is used up, the fitted performance stops improving. They trace the drop to the update itself: a policy-gradient step lowers entropy when the tokens the policy already likes also get positive advantages, so that probability and advantage are positively correlated.

The usual fixes from chapter 5 did not work well in their runs. An entropy bonus was sensitive to its weight, and at 0.01 entropy exploded. A KL penalty to the reference hurt performance. Cui et al. propose instead to clip or penalise the updates of the few tokens with the highest covariance between probability and advantage [8].

DAPO found the clip itself to be one cause [7]. The upper clip limits how far a ratio can rise, which matters most for unlikely tokens. With \(\epsilon = 0.2\), a token at probability 0.01 can rise only to 0.012 within one update, while a token at 0.9 can rise to 1.08, which is no limit at all. So rare tokens with positive advantages cannot gain much. DAPO's Clip-Higher separates the two ends of the band:

\begin{equation} \operatorname{clip}\big(\rho_{i,t},\; 1 - \epsilon_{\mathrm{low}},\; 1 + \epsilon_{\mathrm{high}}\big), \qquad \epsilon_{\mathrm{low}} = 0.2,\;\; \epsilon_{\mathrm{high}} = 0.28. \label{eq:cliphigher} \end{equation}

Stale samples

Generating long completions is slow, so practitioners take several gradient steps per batch of samples. DeepSeek-R1-Zero's training generated 8,192 completions per rollout, split them into 16 minibatches and took one pass over them [2]. DAPO also took 16 gradient steps per rollout [7]. After the first minibatch, \(\pi_\theta\) differs from \(\pi_{\mathrm{old}}\), the ratios move away from 1, and the clip in Equation \eqref{eq:grpo} can act, for the same reason chapter 5 gave for having a clip. How often the clip acts depends on \(\epsilon\), and DAPO's lower bound is 0.2. The first RL stage of DeepSeek-R1 set \(\epsilon = 10\), and the paper says a lower value truncated the gradients of many tokens and hurt performance [2, §3.2.1].

In asynchronous training, one set of GPUs generates completions while another trains, so the samples come from a policy one or more updates old. Chapter 6 covers the correction. Noukhovitch et al. measured how much staleness each method tolerates [9]. Performance fell as the generating policy fell further behind, with online DPO holding up best and PPO and RLOO degrading more, and larger policies tolerated stale samples better. Generating one step behind matched synchronous training and was about 40% faster for an 8-billion-parameter model on an instruction-following task.

Group size trades compute for variance

Each extra completion per prompt costs one more generation. In return, the average has lower variance, the other completions get a better baseline, and a group with no signal becomes less likely. Published choices vary: DeepSeekMath used 64 completions per question, and DeepSeek-R1 and DAPO used 16 [1, 2, 7]. For a fixed number of generated completions, a larger group means fewer distinct prompts per batch. Section 9 measures the trade on a toy problem, and chapter 9 covers sample efficiency in general.

Four of the departures recur.

  • The KL penalty shrinks or disappears. DAPO removes it, and Liu et al. set \(\beta_{\mathrm{KL}} = 0\) for rule-based verifiers [7, 6]. DeepSeek-R1-Zero keeps a small weight but moves the reference forward every 400 steps, so the penalty limits drift over 400 steps rather than over the whole run.
  • Truncated completions get special handling. A completion cut off at the length budget has no final answer, so the verifier scores it wrong even if the reasoning was on track. Tülu 3 gives a reward of −10 to completions without EOS [5]. DAPO masks truncated completions out of the loss and adds a length penalty that grows as a completion nears the budget [7].
  • One pass over each rollout. None of the three runs reuses a rollout for multiple epochs, unlike Spire Mentor's launch setting of two epochs (chapter 5), which the campaign later cut to one.
  • Loss aggregation varies by library. The three forms of Equation \eqref{eq:agg} are all in use, and Dr. GRPO's Table 2 shows that a library's default may not match the paper you are reproducing [6].

Tülu 3 also lists details of its PPO set-up that the textbook does not mention: dropout turned off during RL, and advantages whitened over the batch [5].

8. In Spire Mentor

In Spire Mentor · why the project keeps its critic

Spire Mentor's learner is PPO with a critic (chapters 4 and 5). The reasons the papers above gave for dropping the critic do not hold for it.

  • Credit assignment over long episodes. A run is about 667 decisions long. A group baseline gives one number per episode, so all 667 decisions would share it, as all tokens of a completion share \(\hat A_i\). The critic gives a separate baseline at every decision, and chapter 4's GAE assigns credit with \(\lambda_c = 0.95\) within a combat and \(\lambda_r = 0.97\) over the run.
  • Rewards inside the episode. Floors and bosses pay out during the run, and a value function can learn from those intermediate rewards. A completion's reward arrives only at the end, which is DeepSeekMath's second reason for dropping the critic.
  • A cheap critic. Spire Mentor's critic is one value block on top of the shared trunk, with two heads, \(V_{\mathrm{combat}}\) and \(V_{\mathrm{run}}\) (chapter 4). It is not a second network of the policy's size, which was DeepSeekMath's first reason.

Two of this chapter's mechanisms have direct counterparts in the project. Spire Mentor normalises advantages separately for each decision type, which reweights the types against each other, as GRPO's per-prompt \(s_R\) reweights prompts (chapter 5, Section 11). Its rollouts also run ahead of the learner, which makes samples stale, the same problem that asynchronous RL for language models has to solve. Chapter 6's decoupled PPO caps the importance weight at 2 for that reason.

The project's entropy bonus starts at weights of 0.01 and 0.0125, which decay to 0.002 and 0.006 (chapters 2 and 5). Cui et al. found this fix fragile for language models. The project's bonus also differs in form: it uses the entropy normalised per decision type, and it raises the weight when entropy stays low (chapter 2). A likely reason the bonus works here, not tested in this chapter or in the cited sources, is the size of the action set. Spire Mentor's decisions have about seven options, while a vocabulary has far more, and an entropy bonus spreads probability over all of them.

9. Measured: gradient noise against group size

Section 5 claimed that RLOO is unbiased, that the group-mean estimator is short in scale by \(\frac{n-1}{n}\), and that GRPO's division by \(s_R\) turns the gradient away from \(\nabla J\). A toy problem whose exact gradient is known can test all three.

Measured · a toy problem, not a language model

Set-up. Eight prompts, with success rates \(p_x\) of 0.03, 0.10, 0.25, 0.40, 0.60, 0.75, 0.90 and 0.97. For each prompt the policy is a softmax over eight whole completions, three of them correct with reward 1 and five wrong with reward 0. The parameters are the 64 logits, and the objective is the mean success rate, \(J = \frac{1}{8}\sum_x p_x\). Each completion is one action, which is the bandit view from Section 2. For each group size \(n\) from 2 to 64, figures.py draws 20,000 batches of \(n\) completions per prompt with seed 0. For each batch it computes four estimates of \(\nabla J\) with respect to the logits.

  • No baseline. \(\hat A_i = R_i\).
  • RLOO. Equation \eqref{eq:rloo}.
  • Group mean. \(\hat A_i = R_i - \bar R\), divided by \(n\).
  • GRPO. Equation \eqref{eq:grpo-adv} with the population standard deviation, plus \(10^{-6}\) in the denominator.

Every estimate is averaged over the \(n\) completions, as in Equation \eqref{eq:rloo}. The script compares the mean of each estimator with the exact gradient, whose norm is 0.042, and measures its noise as the inverse signal-to-noise ratio, which is the total variance divided by the squared norm of the estimator's own mean. That ratio ignores the scale of the estimator, so a smaller learning rate cannot make an estimator look less noisy.

The toy problem's measurements. Inverse SNR is variance over squared mean, lower is better. Scale is the projection of the estimator's mean on the exact gradient, divided by the exact gradient's squared norm, so 1 means right on average. The baseline cuts noise, and more so in larger groups. At \(n = 2\), RLOO's inverse SNR is 1.4 times lower than no baseline. At \(n = 64\) it is 2.9 times lower. At \(n = 2\) the leave-one-out baseline is a single other sample, a noisy estimate of \(p_x\), while at \(n = 64\) it is the mean of 63 samples.

The group mean is RLOO scaled down. Its inverse SNR matches RLOO's at every \(n\), and its measured scale is 0.50, 0.75, 0.87, 0.94, 0.97 and 0.98, within 0.002 of \(\frac{n-1}{n}\), as Equation \eqref{eq:rloo-mean} predicts.

GRPO changes direction and scale. At \(n = 2\) its scale is 1.00 and its cosine 1.000, as the identity with RLOO predicts. As \(n\) grows, \(s_R\) approaches \(\sigma_x\) and the mean approaches the oracle gradient of Equation \eqref{eq:arcsin}. The cosine falls to 0.982 at \(n = 64\), on the way to the oracle value of 0.978, an angle of about 12°. The scale rises to 2.24 because the division by \(s_R\) multiplies every prompt's contribution by between 2 and 5.9 in this toy. GRPO is also slightly noisier than RLOO, because \(s_R\) is itself estimated from the group.

Per completion, larger groups get more out of each sample. Without a baseline, inverse SNR times \(n\) stays between 24.1 and 24.4 for every \(n\), so doubling the completions halves the variance and does nothing more. With RLOO the same product falls from 17.1 at \(n = 2\) to 11.2 at \(n = 4\), 9.6 at \(n = 8\) and 8.4 at \(n = 64\). Most of the gain comes by \(n = 8\), and each completion beyond that adds little. The toy does not measure the alternative, which is to spend the same completions on new prompts. It also cannot say how that trade-off looks on a real model, where new prompts also add diversity and each completion costs thousands of tokens.

How far GRPO's direction turns depends on the success rates in the dataset, and this chapter measured only the eight rates listed above.

10. Common confusions

"GRPO is a new kind of algorithm." GRPO is PPO's clipped surrogate from chapter 5, with the critic replaced by a group statistic and a KL penalty added to the loss. Everything chapter 5 says about the ratio and the clip carries over. With a single gradient step per rollout, as in DeepSeekMath, the clip does nothing and GRPO is REINFORCE with a normalised group baseline.

"Subtracting the group mean biases the gradient." It shrinks the scale by \(\frac{n-1}{n}\) and leaves the direction alone, and RLOO removes even the shrinkage. The step that changes the direction is the division by the standard deviation, because it weights prompts differently.

"Each token gets credit for its contribution to the answer." Every token in a completion gets the completion's advantage, by Equation \eqref{eq:seqpg}. A token is credited only through averaging, when it shows up more often in correct completions than in wrong ones.

"The KL penalty keeps the update close to the data." Two different policies are involved. The clip keeps \(\pi_\theta\) close to \(\pi_{\mathrm{old}}\), the policy that generated this batch. The KL penalty keeps it close to \(\pi_{\mathrm{ref}}\), a frozen copy from before training. Removing the KL penalty, as DAPO does, leaves the clip in place.

"A bigger group only reduces variance." A bigger group also improves every completion's baseline and lowers the share of groups with no signal, by Equation \eqref{eq:allsame}. In exchange, it uses generation compute that could have gone to more prompts.

11. Suggested experiments

Run every command from the fork's root. The toy needs only NumPy, and each run takes a few seconds.

  1. Reproduce the measurements.

    The first command prints one line per group size and rewrites figures.json. The second redraws Figures 10.8 to 10.10 in chapter.html. The numbers should match the table in Section 9.

  2. Remove the difficulty bias. In figures.py, set every entry of P_TARGET to 0.5. Run both commands again. All prompts now have the same \(\sigma_x\), so Equation \eqref{eq:arcsin} gives them equal weights. Check whether GRPO's cosine in Figure 10.10 stays at 1. Then put four prompts at 0.5 and four between 0.01 and 0.03, run both commands again, and compare GRPO's cosine with the 0.982 it reached at \(n = 64\) on the original rates.

  3. Try the sample standard deviation. In advantages(), change R.std(1, keepdims=True) to R.std(1, ddof=1, keepdims=True). Run the first command again. At \(n = 2\), GRPO's scale should fall from 1.00 to about 0.71, and it no longer equals RLOO.
