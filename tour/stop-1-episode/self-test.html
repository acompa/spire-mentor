The decision process: self-test

Questions on Chapter 1, The decision process. Every answer is in that chapter.

Answer each question from memory and in writing before you open its answer.

Come back in a few days and do the whole page again.

Recall questions

  1. Supervised learning trains on pairs \((x, y)\). Which two properties of that data does reinforcement learning give up, and what replaces them?

    Answer

    In supervised learning the pairs come independently from one fixed distribution, and nothing the model predicts changes which \(x\) it sees next. In reinforcement learning the agent's choice changes what it sees next. The data is a sequence, and the distribution of that sequence depends on the parameters that training changes. (Section 1)

  2. The chapter requires each row of \(p\) to sum to one only for \(a \in \mathcal{A}(s)\). Why does that range matter in a card game, and what does it demand of the policy? How does Spire Mentor meet that demand, and what is the other common way?

    Answer

    Only actions that are legal in \(s\) have a row in \(p\). Atari and MuJoCo offer every action in every state, so much deep-RL code ignores the condition. A card game does not: Ascender's Bane is in the hand, but "play Ascender's Bane" has no row. The policy must then put probability zero on every \(a \notin \mathcal{A}(s)\) and sum to one over \(\mathcal{A}(s)\). A network with a fixed output layer breaks this, because it gives every action a logit in every state. One fix sets illegal logits to \(-\infty\) before the softmax. Spire Mentor uses the other fix: its network scores only the candidates that the game offers, so an illegal action has no output at all. (Section 4)

  3. Write down how \(p_\theta(\tau)\) factors. Which factors depend on \(\theta\), and why does that let a policy gradient work without a model of the game?

    Answer

    \[p_\theta(\tau) = d_0(s_0) \prod_{t=0}^{T-1} \pi_\theta(a_t \mid s_t)\, p(s_{t+1}, r_t \mid s_t, a_t).\] You follow the trajectory forward and multiply, because each draw depends only on the step before it. Only the \(\pi_\theta\) factors depend on \(\theta\). The start distribution and the dynamics belong to the game. You never need to know them, only to sample from them by playing. When Chapter 5 takes the logarithm and differentiates, the dynamics drop out. (Section 5)

  4. What problem does the discount \(\gamma\) solve? Why may Spire Mentor set \(\gamma = 1\), and why do many episodic systems use \(\gamma < 1\) anyway?

    Answer

    The discount exists for continuing tasks, which have no terminal state. There the undiscounted sum can be infinite, and \(\gamma < 1\) keeps it finite. In an episodic task with a bounded horizon the sum is already finite, so \(\gamma = 1\) is allowed. Many episodic systems still use \(\gamma < 1\) to reduce variance. That is a training choice and not part of the problem. With \(\gamma = 1\), the return \(G_0\) is the run's total reward. (Section 5)

  5. You estimate \(J(\theta)\) by \(\hat J\) and its standard error. Why is the sampling unit the run and not the decision? What goes wrong if you put the number of decisions in the denominator?

    Answer

    Decisions inside one run are not independent draws. They share a seed, a deck, a map and an outcome. A run of several hundred decisions is one draw from \(p_\theta(\tau)\). If you count decisions instead of runs, the standard error shrinks by about \(\sqrt{T}\), and with several hundred decisions per run that error is large. Treating the turns of one user session as independent observations is the same mistake. (Section 6 and Section 11)

  6. The chapter says the Markov property "is a statement about what you put in \(s_t\)". Explain that. Is the simulator's fight state Markov? What does Spire Mentor's policy read instead, and why must the policy not read the true draw order?

    Answer

    The equation holds or fails depending on what the state contains. If the state holds the whole history, it holds trivially. The simulator's fight state is Markov, because it contains the draw pile in its true order, every enemy's move pattern and the random-number generator. The policy does not get that state. It reads tokens built from the belief view, which is the fight as a player could know it. In that view the draw pile is an unordered multiset and the hidden random-number streams are reseeded from 0. A policy that could read the order would learn to play as if it knew the next draw, and that skill would be worthless in the real game. Only the critic reads the true top of the pile, through the PRIV_DRAW section. (Section 4, Section 7 and Section 9)

  7. What does partial observability leave unchanged, and what does it cost? Answer for the policy gradient, the optimum and the critic.

    Answer

    The form of the objective does not change. The trajectory probability still factors, now with observation-kernel factors \(O(o_t \mid s_t)\), and only the policy factors depend on \(\theta\). So the policy gradient of Chapter 5 works without change. The cost is a guarantee about the optimum. The best policy over the agent's summary can be worse than the best policy over the true state, because the summary discards information. A critic \(V_\phi\) that reads only the observation is not Markov in its input. Chapter 4 gives Spire Mentor's critic privileged inputs for that reason. (Section 7)

  8. What is a forced step, and what does Spire Mentor do with one? Why is skipping it safe for training? Why does the process over decision points stay an MDP with \(\gamma = 1\), and what would it become with \(\gamma < 1\) per game step?

    Answer

    A forced step offers one legal action or one merged class. The env applies it without asking the policy, and it makes no row. The plan does not give the reason. The chapter suggests one: a choice from a set of one has probability 1, so its row adds zero to the policy gradient and zero to the entropy, and skipping it saves a network evaluation. The forced steps' rewards join the reward \(r_t\) of the decision before them, and \(\tilde p\) does not depend on the policy. With \(\gamma = 1\) a sum of rewards does not depend on how many game steps a decision spans, so the result is again an MDP with the same objective. With \(\gamma < 1\) per game step, the varying number of forced steps would change the discount between decisions, and the process would be a semi-MDP. (Section 8)

  9. In the Seapunk position, three legal actions are "play a Strike at the Seapunk". What would go wrong if the policy scored each one separately? What makes merging them into a class safe, and why do fight merge keys come from the belief view?

    Answer

    The three Strikes lead to the same next state. Scored separately, one plan, "attack now", would be split across three outputs, and its total probability would depend on how many copies of Strike happen to be in the hand. Merging is safe only if the members of a class are interchangeable. The merge key for a card play is built from what the player can see: the card, its cost, its enchantment, its damage and block numbers, its flags and the target. The plan rejected an older key because it would merge an enchanted Strike with a plain one. Fight keys come from the belief view because keys built from the true state would leak hidden information into the action set itself. (Section 8 and Section 9)

  10. Spire Mentor's first version used tree search for fights and a separate run policy between them. Why did the project move to one network for every decision, and what does that mean for a card picked on floor 3?

    Answer

    With the split, the run network never found out what its deck was like to play, and the search played every fight without knowing what the run needed afterwards. Two attempts to replace the search with a separately trained fight network reached 9% and 12% wins at Ascension 10. Instinct uses one network, so a fight turn and a card reward are rows of one trajectory, scored by one return. A card picked on floor 3 and a block played on floor 40 share the run's final win or loss. (Section 9)

  11. The network averages 667 decisions per run and random play averages 28.2. Why is \(T\) random, and why does its distribution depend on the policy? What explains the higher share of forced steps in random play?

    Answer

    An episode ends at death, a win or a cap, and the policy decides when death happens. A random run is short because it dies early, not because it makes fewer decisions per floor. Random play loses most runs in the first two or three fights, while most of the network's losses come at the final bosses. Forced steps are 0.135 of random play's game steps and 0.069 of the network's. 82% of random play's forced steps are a lone "end turn". The chapter's inference is that random play spends its energy and is left holding cards it cannot afford. (Section 10)

  12. "Q-learning would do the same thing here." What would Q-learning need in this game, and where does it get into the most trouble?

    Answer

    It would need \(Q(s, a)\) for a set of actions that changes size, a target \(\max_{a'} Q(s', a')\) over the next decision's classes, and a state that is not Markov. All three are possible. The trouble is the bootstrap target. It treats the observation as if it were the state, and the max over an observation-based \(Q\) is where partial observability does the most damage. Optimising \(J\) directly, the policy needs no bootstrap target. Only the critic bootstraps, and privileged inputs can restore the Markov property for the critic. (Section 11)

Calculations

  1. Take \(T = 3\), \(r_0 = 0.002\), \(r_1 = 0\), \(r_2 = 1\) and \(\gamma = 1\). Use the recursion \(G_t = r_t + \gamma\, G_{t+1}\) with \(G_T = 0\) to find \(G_2\), \(G_1\) and \(G_0\). Then use Spire Mentor's reward to find the return of a won run that reaches floor 46.

    Answer

    Start at the end. \(G_3 = 0\).

    \(G_2 = r_2 + G_3 = 1 + 0 = 1\).

    \(G_1 = r_1 + G_2 = 0 + 1 = 1\).

    \[G_0 = r_0 + G_1 = 0.002 + 1 = 1.002.\]

    A won run earns 1 for the win, 0.05 for each of three bosses and 0.002 for each new floor. So \[G_0 = 1 + 3 \times 0.05 + 46 \times 0.002 = 1 + 0.15 + 0.092 = 1.242.\] (Section 5 and Section 6)

  2. Over 200 seeds the network wins 166 runs. Its won runs have a mean return of 1.242 and its lost runs average 0.189. The standard deviation of \(G_0\) across runs is 0.398. Compute \(\hat J\), its standard error, and the share of \(\hat J\) that comes from the win term.

    Answer

    There are \(200 - 166 = 34\) lost runs.

    \[\hat J = (166 \times 1.242 + 34 \times 0.189) / 200 = (206.17 + 6.43) / 200 \approx 1.063.\]

    \[\widehat{\mathrm{se}}(\hat J) = 0.398 / \sqrt{200} = 0.398 / 14.14 \approx 0.028.\]

    The win term pays 1 per won run, so it contributes \(166 / 200 = 0.83\). Its share is \(0.83 / 1.063 \approx 78\%\). Lost runs add only \(34 \times 0.189 / 200 \approx 0.03\). (Section 6 and Section 10)
