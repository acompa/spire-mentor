Evaluating agents

To compare two agents, play both on the same seeds and count the seeds where only one of them wins. That count sets how precise the comparison is and how many games it needs. It also sets how far the best of several checkpoints overstates its own score.

1. An evaluation is an experiment with one bit per game

Chapters 5, 6 and 7 each changed how the network is trained, and each change raises the same question: does the new network win more often than the old one? The training curve cannot answer that. It averages games of the sampling policy, on seeds the learner has partly fitted, while the weights are still moving. You need a separate measurement, in which you freeze the network, play it on fresh games, and count the wins.

That measurement is an experiment with a sample size, and a poor one by the standards of supervised learning. There the test set is fixed and large, and two models are scored on the same examples. In reinforcement learning you create the test set by playing games, and each game is expensive and returns one bit. A Slay the Spire 2 run takes about 650 decisions and ends in a win or a loss, so a thousand runs cost 650,000 forward passes of a transformer and return 1,000 bits.

Henderson and colleagues showed that reported gains on standard deep RL benchmarks often sat inside the spread between random seeds of one algorithm [1]. Agarwal and colleagues reanalysed published Atari results and found that conclusions drawn from point estimates over a few runs often reversed once intervals were drawn [2]. Both papers are about the variance across training runs. The subject here is the variance of evaluating one frozen network, which you control with a seed list and a budget.

You already know power calculations, crossover designs, and CUPED, and this chapter uses exactly those tools. Three facts are specific to agents. A seed fixes the game's random environment, so two agents can play the same game. The gain from pairing them on seeds has an exact formula in terms of how often they disagree. And the seeds used to pick a checkpoint overstate its score by an amount you can compute.

2. A win rate is a binomial estimate

A seed is an integer that initialises the game's random number generators. It fixes the map of each act and the list of fights each act offers, while card rewards, shuffles and the enemies' moves come from streams that advance as the game is played. Fix a policy \(\pi_\theta\), draw seeds \(i = 1, \dots, n\), play the policy greedily on each, and let \(X_i \in \{0, 1\}\) record whether the run on seed \(i\) was won. Chapter 3's return with the win bonus is close to \(X_i\), but the project reports the bit, so this chapter uses the bit.

Definition 8.1 · Win rate

The win rate of a policy is \(p = \Pr(X = 1)\) for a seed drawn from the seed distribution. Its estimate on \(n\) seeds is

\begin{equation} \hat p = \frac{k}{n}, \qquad k = \sum_{i=1}^{n} X_i \sim \operatorname{Binomial}(n, p). \label{eq:phat} \end{equation}

Here \(k\) is the number of wins. Each \(X_i\) is a Bernoulli draw with the same \(p\), because the design treats the seeds as independent draws and greedy play makes the outcome a fixed function of the seed. Section 8 explains why the independence of the seeds is an assumption. Two consequences follow:

\begin{equation} \mathbb{E}[\hat p] = p, \qquad \operatorname{Var}(\hat p) = \frac{p(1-p)}{n}. \label{eq:var} \end{equation}

The estimate is unbiased, and its standard deviation shrinks as \(1/\sqrt{n}\). At \(p = 0.8\) and \(n = 400\) the standard error is \(\sqrt{0.16/400} = 0.02\), or two percentage points. The difference between easy and hard seeds does not appear in Equation \eqref{eq:var}, and it does not need to, because one outcome is a Bernoulli draw whatever mix of easy and hard seeds produced it. The rate \(p\) already averages over that mix. Section 11 comes back to this, because it is the most common misreading of a gap between two panels.

Wilson's interval stays between 0 and 1

A 95% confidence interval is a procedure that covers the true \(p\) in 95% of repeated samples. The familiar interval puts \(\hat p\) in place of \(p\) in Equation \eqref{eq:var}:

\begin{equation} \hat p \pm z \sqrt{\frac{\hat p (1 - \hat p)}{n}}, \qquad z = z_{0.975} \approx 1.96. \label{eq:wald} \end{equation}

This is the Wald interval, and it fails for good agents, whose win rates sit near 1. At 19 wins in 20 games it gives \(0.95 \pm 0.096\), which runs past 100%, and at 20 wins in 20 it has zero width. It plugs in a variance estimated from the same small count it is meant to judge.

Wilson (1927) keeps the unknown \(p\) in the variance [3]. He asks which values of \(p\) are consistent with the observed \(\hat p\), and keeps a value if \(\hat p\) lies within \(z\) of that value's own standard errors:

\begin{equation} (\hat p - p)^2 \le z^2 \, \frac{p(1-p)}{n}. \label{eq:wilson-ineq} \end{equation}

This is a quadratic inequality in \(p\). We expand it and take its two roots, which gives the Wilson score interval:

\begin{equation} p \in \frac{1}{1 + z^2/n} \left[ \hat p + \frac{z^2}{2n} \pm z \sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}} \right]. \label{eq:wilson} \end{equation}

The centre is \((k + z^2/2)/(n + z^2)\), the win rate you would get after adding \(z^2 \approx 3.84\) games, half of them wins. So the interval is centred as if about four extra games, two won and two lost, had been played, which moves the centre from \(\hat p\) toward one half by \(z^2(\tfrac12 - \hat p)/(n + z^2)\). The interval never leaves \([0, 1]\). At 20 wins in 20 games it gives \([0.84, 1]\), so twenty straight wins rule out a 70% agent but not an 85% agent. The project computes Equation \eqref{eq:wilson} directly.

On this chapter's 600 seeds the Ironclad network won 482 of 600 games, a win rate of 80.3%, with a Wilson interval from 77.0% to 83.3%. The half-width of 3.2 percentage points matches Equation \eqref{eq:var}, which predicts \(1.96\sqrt{0.8 \times 0.2/600}\), about three points. Halving that width would take four times the games.

3. Paired seeds remove the noise both networks share

Now compare two policies, network 1 and network 2. The obvious design gives each network its own \(n\) seeds, and the difference of two independent binomial estimates then has variance

\begin{equation} \operatorname{Var}(\hat p_1 - \hat p_2) = \frac{p_1(1-p_1) + p_2(1-p_2)}{n}. \label{eq:unpaired} \end{equation}

Here \(p_1\) and \(p_2\) are the two true win rates. With both near 0.8 the variance is \(0.32/n\), so at \(n = 1{,}000\) the standard error is 1.8 points and a two-point gain would be only about one standard error.

A crossover trial gives one patient two treatments in sequence and has to model the carry-over between them. Seeds need no sequence. Both networks can play seed 170,000,000, and both meet the same maps and the same lists of fights. Simulation practice calls this common random numbers. You run two systems on the same random inputs so that their difference has less noise [4]. For agents the design is paired seeds, in which both networks play every seed and the seed is the unit of analysis.

Each network wins or loses the game, and the pair of results puts the seed in one of four cells. Over a panel of \(n\) seeds the cells hold counts.

A seed in cell a or cell d gave both networks the same result. It adds the same amount to both win rates and cancels from the difference. It tells you the seed was easy or hard, and nothing about which network is better.

The variance, written out

Let \(X_i\) and \(Y_i\) be the outcomes of networks 1 and 2 on seed \(i\), and let \(D_i = X_i - Y_i \in \{-1, 0, 1\}\). The paired estimate of the difference is

\begin{equation} \hat\Delta = \frac{1}{n} \sum_{i=1}^{n} D_i = \hat p_1 - \hat p_2 = \frac{b - c}{n}, \label{eq:delta} \end{equation}

where \(b\) counts the seeds that only network 1 wins and \(c\) counts the seeds that only network 2 wins. The point estimate equals the unpaired one, but its variance does not. Because the \(D_i\) are independent across seeds, we have

\begin{equation} \operatorname{Var}(\hat\Delta) = \frac{\operatorname{Var}(X) + \operatorname{Var}(Y) - 2\operatorname{Cov}(X, Y)}{n}. \label{eq:pairedvar} \end{equation}

The covariance term holds the whole gain. A seed that is easy for one network is usually easy for the other, so \(\operatorname{Cov}(X, Y) > 0\), and pairing subtracts it. We write the cell probabilities as \(\pi_a, \pi_b, \pi_c, \pi_d\). Then \(D = 1\) with probability \(\pi_b\) and \(D = -1\) with probability \(\pi_c\), so

\begin{equation} \operatorname{Var}(D) = \mathbb{E}[D^2] - \mathbb{E}[D]^2 = (\pi_b + \pi_c) - (\pi_b - \pi_c)^2 = \delta_d - \Delta^2. \label{eq:vard} \end{equation}
Definition 8.2 · Discordance

The discordance \(\delta_d = \pi_b + \pi_c\) is the probability that the two networks disagree on a seed's outcome, with one winning and the other losing. Its estimate is \((b + c)/n\). Seeds in cells b and c are the discordant pairs.

So the precision of a paired comparison depends on how often the networks disagree, not on how often they win. The campaign's documents call this quantity \(d\). Below, \(\delta_d\) is the discordance and \(d\) stays the "both lose" cell. In this chapter \(\pi_a\) to \(\pi_d\), \(\rho\), \(\hat\phi\) and the CUPED \(\theta\) also keep their usual statistical meanings, not the tour's meanings of policy, importance ratio, critic parameters and policy parameters. Two networks that differ in a few decisions per run agree on most seeds, which gives a small \(\delta_d\) and a small variance. If the two outcomes were independent, \(\delta_d\) would equal \(p_1(1-p_2) + p_2(1-p_1)\), and Equation \eqref{eq:vard} would reduce exactly to Equation \eqref{eq:unpaired}, because \(\delta_d - \Delta^2 = p_1(1-p_1) + p_2(1-p_2)\). Pairing helps when the networks disagree less often than independent outcomes would.

Pairing works like CUPED with \(\theta = 1\)

CUPED reduces the variance of a treatment metric \(M\) by subtracting \(\theta (C - \mathbb{E}C)\), where \(C\) is the same user's metric from before the experiment and \(\theta = \operatorname{Cov}(C,M)/\operatorname{Var}(C)\) [5]. Deng and colleagues do not discuss paired seeds, so the comparison is this chapter's analogy. Pairing is a control variate with \(\theta = 1\), which is not CUPED's variance-minimising choice. Network 2's result on the same seed is the covariate, and its mean is already the other arm. If the two networks' outcomes have correlation \(\rho\), the ratio of paired to unpaired variance is

\begin{equation} \frac{\operatorname{Var}_{\text{paired}}(\hat\Delta)}{\operatorname{Var}_{\text{unpaired}}(\hat\Delta)} = 1 - \frac{2\rho\,\sigma_1\sigma_2}{\sigma_1^2 + \sigma_2^2} \approx 1 - \rho, \label{eq:ratio} \end{equation}

where \(\sigma_1^2 = p_1(1-p_1)\) and \(\sigma_2^2 = p_2(1-p_2)\). For binary outcomes \(\rho\) is the phi coefficient of the 2×2 table, and the approximation holds when \(\sigma_1 \approx \sigma_2\). So \(n\) paired seeds are worth about \(n/(1-\rho)\) unpaired seeds per network. At \(\rho = 0.5\), pairing doubles the effective sample and halves the games that a given precision needs. Both designs play \(2n\) runs. Pairing only decides which seeds the two networks share.

The two published networks disagreed on 142 of this chapter's 600 seeds. Network 1 alone won \(b =\) 64 seeds and network 2 alone won \(c =\) 78, so \(\hat\delta_d =\) 0.237, against 0.302 for independent outcomes at these win rates. The phi coefficient is 0.22, and the paired variance is 0.78 times the unpaired variance. Figure 8.5 puts that measurement on the curve of standard error against discordance.

4. McNemar's test uses only the seeds where the networks disagree

To test whether the two networks are equally good, you need a null distribution for \(b\) and \(c\). Condition on the number of discordant seeds, \(m = b + c\). Under the null hypothesis \(\pi_b = \pi_c\), each discordant seed falls on either side with probability one half, so

\begin{equation} b \mid m \;\sim\; \operatorname{Binomial}\!\left(m, \tfrac{1}{2}\right) \quad \text{under } H_0 : \pi_b = \pi_c. \label{eq:mcnull} \end{equation}

The concordant counts \(a\) and \(d\) do not appear, which is Figure 8.4 written as a formula. Given \(m\) disagreements, the only evidence is how they split. The exact two-sided p-value doubles the smaller tail:

\begin{equation} p_{\text{exact}} = \min\!\left(1,\; 2 \sum_{j=0}^{\min(b,c)} \binom{m}{j} 2^{-m}\right). \label{eq:mcexact} \end{equation}

McNemar (1947) derived the large-sample version for correlated proportions [6]. Under the null, his statistic is approximately \(\chi^2_1\):

\begin{equation} \chi^2 = \frac{(b - c)^2}{b + c}. \label{eq:mcchi} \end{equation}

Take 44 discordant seeds that split 30 to 14. The chi-square statistic is \(16^2/44 = 5.8\), and the exact p-value, twice the probability that 44 fair coins show 14 or fewer heads, is about 0.023. If you had played 4,000 seeds and seen the same 30-to-14 split, the p-value would be the same. The 3,956 concordant seeds add nothing to the test. They do change the effect size, because \(\hat\Delta = 16/n\) is 36 points at \(n = 44\) and 0.4 points at \(n = 4{,}000\).

Newcombe's interval adds the pairing to two Wilson intervals

A p-value says whether zero is a plausible difference, and an interval says which differences are plausible. The Wald interval \(\hat\Delta \pm z\sqrt{(\hat\delta_d - \hat\Delta^2)/n}\) has the same faults here as for one proportion. Newcombe (1998) compared ten methods. His summary recommends two profile-likelihood methods and says that a simpler hybrid, which builds the paired interval from the Wilson intervals of the two margins, also performs well [7]. Let \((l_1, u_1)\) and \((l_2, u_2)\) be the Wilson intervals of \(\hat p_1\) and \(\hat p_2\), and let \(\hat\phi\) be the phi coefficient of the table. His method 8 is

\begin{equation} \begin{aligned} L &= \hat\Delta - \sqrt{(\hat p_1 - l_1)^2 - 2\hat\phi\,(\hat p_1 - l_1)(u_2 - \hat p_2) + (u_2 - \hat p_2)^2}, \\ U &= \hat\Delta + \sqrt{(u_1 - \hat p_1)^2 - 2\hat\phi\,(u_1 - \hat p_1)(\hat p_2 - l_2) + (\hat p_2 - l_2)^2}. \end{aligned} \label{eq:newcombe} \end{equation}

Each side combines two Wilson half-widths the way Equation \eqref{eq:pairedvar} combines two standard errors, and the \(-2\hat\phi\) term subtracts the covariance that pairing removes. With \(\hat\phi = 0\) the formula is Newcombe's interval for independent samples. The hybrid his summary names is method 10, which is method 8 with a continuity correction to \(\hat\phi\). When \(ad - bc\) is positive, method 10 replaces the numerator of \(\hat\phi\) with \(\max(ad - bc - n/2,\ 0)\). The project's code computes method 8 and labels it method 10. On this chapter's table the two methods give the same interval to one decimal. The project checks its method 8 interval with a bootstrap that resamples whole seeds, so that both networks' results on a seed stay together.

5. Discordance sets the seeds you need and the hours they cost

Before you run a comparison, ask the reverse question: given \(n\) seeds, what is the smallest true difference the test would reliably detect? Power is the probability that the test rejects the null when the true difference is \(\Delta\), and the minimum detectable effect at 80% power, MDE80, is the \(\Delta\) at which the power is 0.8.

For large \(m\), \(\hat\Delta\) is approximately normal. Under the null its variance is \(\delta_d/n\), which is Equation \eqref{eq:vard} with \(\Delta = 0\), and under the alternative it is \((\delta_d - \Delta^2)/n\). A two-sided test at level \(\alpha\) rejects when \(|\hat\Delta| \gt z_{1-\alpha/2}\sqrt{\delta_d/n}\). We set the probability of that event to \(1 - \beta\) at a true \(\Delta\) and solve for \(n\):

\begin{equation} n = \frac{\left( z_{1-\alpha/2}\sqrt{\delta_d} + z_{1-\beta}\sqrt{\delta_d - \Delta^2} \right)^2}{\Delta^2}. \label{eq:connor} \end{equation}

This is the sample size for paired proportions usually attributed to Connor (1987) [8]. Its form here was checked against secondary sources that implement it, not against the paper. A difference of a few points against a discordance of a few tenths gives \(\Delta^2 \ll \delta_d\), so we drop \(\Delta^2\) and invert:

\begin{equation} \text{MDE}_{80} = \left(z_{1-\alpha/2} + z_{0.80}\right)\sqrt{\frac{\delta_d}{n}} \approx 2.80\sqrt{\frac{\delta_d}{n}} \quad (\alpha = 0.05). \label{eq:mde} \end{equation}

Three things follow from Equation \eqref{eq:mde}. The MDE grows with \(\sqrt{\delta_d}\), so comparing two similar networks is cheap and comparing two very different networks is not. It shrinks as \(1/\sqrt n\), so halving it costs four times the seeds. And the unknown is \(\delta_d\), not \(p\), so an experiment plan has to guess how often the candidate will disagree with the baseline. At the stricter level \(\alpha = 0.01\) the multiplier becomes \(2.576 + 0.842 = 3.42\), and the same MDE needs about 1.5 times as many seeds.

The length of a run turns seeds into hours. If a run takes \(L\) decisions and the machine plays \(R\) decisions per second, a paired comparison of two networks costs

\begin{equation} \text{hours} = \frac{2\, n\, L}{R \cdot 3600}. \label{eq:hours} \end{equation}

Together, Equations \eqref{eq:mde} and \eqref{eq:hours} turn a hoped-for effect into a bill. Suppose a change should gain 2 points and you guess \(\delta_d = 0.2\). Solving Equation \eqref{eq:mde} for \(n\) gives \(n = (2.80/0.02)^2 \times 0.2 = 3{,}920\) paired seeds, which at \(L = 700\) and \(R = 800\) is 1.9 hours of play. If you guess \(\delta_d = 0.3\), you need 5,880 seeds and 2.9 hours. If the change might gain only 1 point, multiply both numbers by four.

On this Mac a run averaged 647 decisions. At the tour's idle-machine rate of 800 decisions per second on ten threads, which no committed measurement records, a 4,000-seed paired comparison takes 1.8 hours. The run behind this chapter shared the machine with other jobs and managed 284 decisions per second on 3 threads, at which the same comparison takes 5.1 hours.

6. The best checkpoint looks better on the seeds that chose it

Training produces many candidates. A checkpoint is saved every few hundred million decisions, and each one has a raw copy and one or more exponential moving averages of its weights. The project plays all candidates on the same development panel and picks one by its score there, so the winner's score on that panel is too high. This is the winner's curse. Cawley and Talbot showed that in model selection it is often as large as the differences between the methods being compared [9].

For paired seeds you can compute its size. Suppose \(K\) candidates all have the same true win rate \(p\) and play the same \(n\) seeds. We model each estimate as a shared seed effect plus a candidate effect:

\begin{equation} \hat p_k = p + \sigma\left(\sqrt{\rho}\, Z_0 + \sqrt{1-\rho}\, Z_k\right), \qquad k = 1, \dots, K, \label{eq:selmodel} \end{equation}

Here \(\sigma^2 = p(1-p)/n\), \(\rho\) is the correlation between any two candidates' estimates, and \(Z_0, Z_1, \dots, Z_K\) are independent standard normals. \(Z_0\) is the panel's luck, which all candidates share, and \(Z_k\) is candidate \(k\)'s own luck on the panel. Selection takes the maximum over \(k\), and only the \(Z_k\) term varies with \(k\):

\begin{equation} \mathbb{E}\!\left[\max_k \hat p_k\right] - p = \sigma\sqrt{1-\rho}\; e_K, \qquad e_K = \mathbb{E}\!\left[\max_{k \le K} Z_k\right]. \label{eq:selbias} \end{equation}

Here \(e_K\) is the expected maximum of \(K\) independent standard normals, with \(e_2 = 1/\sqrt\pi \approx 0.56\), \(e_3 \approx 0.85\), and \(e_9 \approx 1.49\). The shared luck \(Z_0\) does not bias the selection, though it is still in the reported number. To bring in the discordance, note that by Equation \eqref{eq:selmodel} two candidates with equal true rates have \(\operatorname{Var}(\hat p_j - \hat p_k) = 2\sigma^2(1-\rho)\), and by Equation \eqref{eq:vard} with \(\Delta = 0\) the same variance is \(\delta_d/n\). Setting the two equal gives

\begin{equation} \text{optimism} = e_K \sqrt{\frac{\delta_d}{2n}}. \label{eq:optimism} \end{equation}

So the discordance that sets the power of a paired test also sets the bias of selecting on the panel. Candidates that rarely disagree give little optimism, and many candidates on a small panel give a lot. The derivation assumes equal true rates, which is the worst case for the bias, and the same \(\rho\) for every pair. Figure 8.6 checks Equation \eqref{eq:optimism} against simulation.

The two published networks give a direct check with \(K = 2\). Split the 600 seeds in half at random, pick the network that won more on the first half, and score it on both halves. Over 4,000 random splits the chosen network looked 0.90 points better on the half that chose it, and the Ironclad network was chosen in 14.3% of the splits. Equation \eqref{eq:optimism} gives 1.12 points for two candidates on 300 seeds, which is the worst case. One likely reason the measured gap is smaller is that the two networks are not equally good. When one is better, selection usually picks it for the right reason, and the bias shrinks. Sampling noise on one 600-seed panel can also explain a gap this size.

The remedy is to give each set of outcomes one role. Your notes on off-policy evaluation name three. Training data fits the parameters, selection evidence chooses among candidates, and final-evaluation evidence supports the reported claim after the selection is frozen, without having touched the selection. For agents, that means one panel to pick a network and a different panel to report its score.

7. Pre-registration fixes the analysis before the data exist

Selection is one of many ways to read data so that a result looks better than it is, and most of the others are not deliberate either. Each of these choices is defensible on its own:

  • Drop the seeds that errored, or count them as losses.
  • Compare against the baseline that looks weakest.
  • Report the variant that scored highest.
  • Stop collecting games when the p-value crosses 0.05.

Make these choices after you see the data and the reported p-value loses its meaning, because the test you report was one of many you could have reported.

Pre-registration fixes these choices in writing before the data exist. It names the panels, the contrasts, the statistics, the thresholds, and the action on a failure. Nosek and colleagues describe it as the split between prediction and postdiction [10]. A test written before the data is a prediction, and the same test written after the data is a description. A plan can still change after the data arrive, but each change has to be recorded with when it was made and whether the data it touches already existed. That record is an amendment.

A sealed panel enforces the final-evaluation role from Section 6 mechanically. Its seeds are played and the results go to a place nobody reads. Only a hash of the results file is published, so any later change to the file would show, and the pre-registered scorer reads the panel once, after everything that could depend on it is committed. One read matters because of the selection effect again, one level up. A test panel read to pick a checkpoint, read again to pick a variant, and read a third time to report has become a selection panel three times over, and its number carries Equation \eqref{eq:optimism} with a \(K\) that nobody counted. Nobody has to cheat for that to happen.

8. Where a real campaign departs from the textbook

The textbook procedure is short: draw \(n\) seeds, play both networks, count \(b\) and \(c\), and test. A real campaign departs from it in six places, each for a reason.

Some runs never finish. A run can crash, hang, or hit a decision cap. A cap counts as a loss for the network that hit it, since a network that cannot finish a fight in 1,000 decisions has not won that fight. A crash is missing data, and the seed is re-run once on the same build. A hang is booked as a timeout, which is also missing data but is not re-run. If the baseline's result is still missing, the seed leaves the contrast, and if only the candidate's result is missing, the seed counts as a candidate loss. More than 0.5% of such seeds make the whole contrast invalid. The scorer's docstring explains why a timeout is missing data and not a loss. A timeout says nothing about the run, and scoring a baseline timeout as a loss would favour the candidate. The pre-registration gives no reason for treating the baseline and the candidate differently. Read as a whole, the rule decides each ambiguous case against the candidate, though that reading is this chapter's and not the record's.

Both networks run on one engine build. Common random numbers assume that the same random inputs reach both networks. A change to the simulator, even a bug fix, can change what a seed produces, and a candidate on a new engine against a baseline on the old one is then unpaired at best and confounded at worst. The scorer marks a contrast invalid when the two networks' engine builds differ, and when the engine changed during the campaign, every baseline was played again on the new engine.

The pairing weakens as the two games diverge. The engine draws from named random streams, and each stream advances only on its own kind of event. Each act's map comes from its own stream, which depends only on the seed, so both networks see the same maps. The lists of hallway fights, elites and bosses for every act are drawn when the run starts, so a network's third hallway fight in an act is always the third entry of that list. Card rewards, shops, shuffles, enemy moves and unknown rooms draw from streams that advance with play. Once one network takes an extra card reward, its later draws from the reward stream differ from the other network's. The pairing is therefore tightest early in a run. How fast it weakens is not measured here.

Evaluation plays greedily, and training samples. Chapter 2 explained why training samples its actions. Evaluation plays the most probable action, so a run is a fixed function of the seed and the engine's streams are the only randomness. The reported number is the greedy policy's win rate, not the win rate of the policy that generated the training data.

Several contrasts share one error budget. A campaign tests more than one claim. The pre-registered bars are tested in a fixed order, each at its own level, and testing stops at the first failure, which bounds the familywise error. Descriptive contrasts get a Holm adjustment.

The seed distribution is a choice. Every panel is a block of consecutive integers that no earlier experiment used. The design assumes that the game maps any integer to a typical game, so that a block of integers is as good as a random sample. Section 10 checks that assumption on two blocks, which can show a gross failure but cannot confirm it.

9. How Spire Mentor evaluates a network

Three programs do the work. A panel is a named block of seeds with a flag that marks it sealed. The runner plays one checkpoint greedily on a slice of a panel, spread over a pool of worker processes, and writes one record per seed with the outcome, the number of decisions, and the act and floor where the run ended. The scorer reads two networks' records, pairs them by seed, and applies the missing-data rule from Section 8. It then builds the 2×2 table and computes the exact McNemar p-value, Newcombe's interval, and a paired bootstrap that resamples whole seeds 20,000 times as a cross-check.

The record does not say why the project chose the exact McNemar test and Newcombe's interval over a z-test and a Wald interval. At the project's sample sizes it makes little difference. An earlier 400-seed evaluation printed both intervals for one contrast, scored at two ascension levels, and they agreed to within 0.03 points.

Selection uses DEV and reporting uses TEST, the evidence roles of Section 6. Determinism checks get their own SMOKE panel, so a check of the engine never touches a TEST seed. A fifth panel, SMOKE_SEALED, has SMOKE's seeds and TEST's sealing rules, so the sealing code can be tested without a TEST seed. The measurements here use two further blocks, from 170,000,000 and from 171,000,000, that no campaign panel overlaps.

In Spire Mentor · the sealing

The test panel's records were written outside every working copy, to a directory that only the owner can read. The programs that played them printed only row counts, error counts and a SHA-256 hash of the file, and each hash was committed beside the pre-registration. Before the read, the only way to check that a test run was alive was to list files and count lines. Printing, searching or loading a record was forbidden, and the tooling enforced it. The runner looked only at each record's seed and whether it errored, and it discarded the progress line that would have shown a win rate. One scorer read the panel once, and it refuses to read TEST before the unseal time in panels.py.

The plan states these rules without a reason. The nearest one is in the project's training playbook, which asks you to commit the decision rule before any data exists, because that commit "is what makes 'every level improved' a finding rather than a story fitted afterwards." The plan also records a case of the bias the seal prevents. The AlphaDefect agent's reported 56.1% had been picked on 384 of its 1,000 seeds, and it scored 59.1% on those 384 seeds and 54.2% on the other 616.

In Spire Mentor · the bars and their power

The pre-registration named four bars before training began. The must-pass bar required a gain of at least 5 points over the best earlier agent without search, with exact McNemar \(p \lt 0.01\) on the 4,000 sealed seeds, and the plan computed its power. At a guessed discordance of 0.25, Equation \eqref{eq:vard} gives a paired standard error of \(\sqrt{0.25/4000} = 0.79\) points, so a true gain of 5 points would pass with probability 0.51 and a true gain of 6 points with probability 0.90. In the plan's words, "a true +5pp is a coin flip by design." The guess of 0.25 came from eight earlier pairs of networks, which disagreed at 0.71 to 0.90 times the rate of independent outcomes.

The same arithmetic decided what not to run. The plan admits an experiment only if its result can change a decision that week, and it moved several recipe comparisons to later work on that ground. For one of them, the detectable effect at the affordable size was 3.1 to 5.3 points, against a plausible effect of 0.45 to 2 points. The plan sizes later recipe experiments at 4,000 seeds per panel, where the detectable effect is about 2 points, but the record does not show that these experiments have run.

In Spire Mentor · selection, then the single read

The plan wrote the selection rule in advance too. Nine candidates played the 2,000 development seeds: the final checkpoint and the two before it, each in its raw form and under two weight averages. The default candidate was fixed in advance, and a switch to another required a paired gain of at least 0.5 points. The plan chose that threshold by simulating the regret of different thresholds, which came to 0.55 points at a 0.5-point threshold and 0.96 points at a 1.5-point threshold. One candidate cleared it, the 9.0-billion-decision checkpoint under the slower weight average, at 81.40% on DEV-2000 and 1.2 points above the default. The plan warned to expect 1 to 2 points of optimism on DEV.

The sealed panel was read once, on 2026-11-17. That network won 3,255 of 4,000 games, 81.38%, with a Wilson interval of 80.14% to 82.55%, and every bar passed. Against the best earlier agent without search, the paired difference was +69.5 points, with 2,810 discordant seeds against 30. The drop from DEV to TEST was 0.02 points, smaller than the warning. One read cannot measure an expected optimism, and the record gives no discordance for the nine candidates. The campaign log's comparison of the stop checkpoint's two weight averages, \(-1.20\) points with an interval of \(-3.14\) to \(+0.74\) on 2,000 seeds, implies a discordance of about 0.2. With that value, Equation \eqref{eq:optimism} puts the worst-case optimism of nine candidates on DEV-2000 at about 1 point. The TEST estimate's own standard error is about 0.6 points and the DEV estimate has its own noise, so a drop of 0.02 points fits both no optimism and an optimism near 1 point.

In Spire Mentor · four amendments

The pre-registration sets its own rule for amendments. An amendment may only tighten a rule whose data does not yet exist, and each amendment is one commit. By the end of the campaign the amendments were numbered up to 19, and from Amendment 4 on most are labelled "recorded deviation". Each of those records a change that the strict rule did not allow, with when it was made and what data existed. Four of them show how the mechanism worked:

  • A rule fires (Amendment 2). A side experiment had a written go rule, a gain of at least 2 points with the interval's low end above zero. A plan change had already stopped the experiment, and its final read was +0.4 points, with an interval of −2.5 to +3.2. The rule said no, so the champion's recipe stayed on the main run's checkpoint pair.
  • A recorded deviation (Amendment 4). An early gate required 85% agreement with the teacher's combat actions. The student scored 0.805 while already beating the teacher by 5.4 points, with McNemar \(p = 0.00016\). The rule said to fix the student and relaunch, and the user waived it. The amendment states that the waiver was made after the read.
  • One engine build (Amendment 6). The engine changed during training. Every baseline was played again on the new engine, on DEV and on sealed TEST, and the old sealed TEST files stayed unread. Readings from before and after the change were compared only through a bridge, the same checkpoint played on both engines.
  • A switch after the data (Amendment 10). One weight average read 4.05 points above the other, with \(p = 0.002\), so the routine reads switched to it. The amendment re-points the older rules that read the old average and leaves the checkpoint-selection rule, its default and the stall floors unchanged. Each comparison stays paired on shared seeds, and no rule compares a new variant's number with an old variant's.
In Spire Mentor · differences within a panel, never rates across panels

An earlier pilot scored the same network on two 200-seed panels, each played at 11 ascension levels, which is 2,200 runs per panel. The weights were confirmed bit-identical, yet the network scored 43.1% on one panel and 47.2% on the other. The pilot's note calls the gap seed-panel variance of about 2.9 standard errors. That figure treats the 2,200 runs as independent, and they are not: each seed is played 11 times, so the true standard error is larger and the gap is less surprising than 2.9 sigma suggests. Since then the playbook's rule has been to compare differences within one panel and never rates across panels. Section 10 measures how far two panels move the same network here, and Section 11 discusses what a 2.9-sigma gap can and cannot mean.

Measured · panel variance

Across its six 100-seed slices the Ironclad network ranged from 77.0% to 87.0%, a spread of 10.0 points. The binomial standard deviation of one slice is 4.0 points, and the expected range of six independent draws is about 2.5 standard deviations, so luck alone predicts a spread near 10.1 points. The all-character network spread 12.0 points against a slice standard deviation of 3.8.

Network 1's rate was 1.3 points higher on the first 300-seed panel than on the second, with a two-proportion p of 0.68, and network 2's was 4.0 points higher, with p = 0.2. Binomial sampling alone produces gaps of this size, which is why the campaign compared differences on one panel and not rates across panels.

11. Common confusions

"Hard seeds make panels vary more than the binomial says." They do not, if each seed is played once and the seeds are drawn independently. A panel's win count is a sum of independent Bernoulli draws. Their common probability \(p\) is already the average over easy and hard seeds, so Equation \eqref{eq:var} includes that variation. The variation between seeds does change the paired comparison, because it is the reason that \(\operatorname{Cov}(X, Y) > 0\). A 2.9-sigma gap between two panels for identical weights has three explanations. It is a rare draw, with a two-sided \(p \approx 0.004\), which becomes unremarkable once you count how many panel comparisons a project makes. Or something else differed between the reads, such as the engine, the settings, or how the seed blocks map to games. Or the runs were not independent. The pilot played each seed at 11 ascension levels, so a hard seed counted 11 times, and the binomial standard error over 2,200 runs was too small. Section 10's slices show what pure sampling produces.

"Overlapping intervals mean no significant difference." Two intervals for single rates can overlap while the paired interval for their difference excludes zero. Pairing removes the shared seed noise that both single intervals contain. Test the difference directly.

"More concordant seeds make the McNemar test stronger." The test conditions on the discordant count \(m\), as Equation \eqref{eq:mcnull} shows. Concordant seeds dilute the effect size \(\hat\Delta = (b-c)/n\) and narrow its interval. They do not change the p-value for a given split of \(b\) and \(c\). Power grows with \(n\) only because \(m\) grows with \(n\).

"The best checkpoint's development score is its score." That score is the maximum of \(K\) noisy estimates, and Equation \eqref{eq:optimism} says how far it is biased upward. In supervised learning this is the validation-set optimism that you correct with a held-out test set. The difference in RL is that each panel read costs hours, and that cost tempts you to reuse a panel.

"A Q-learning return curve is an evaluation." The training curve averages episodes of the exploring policy, on seeds the learner keeps adapting to, from a network that changes between episodes. It tells you that training is alive. A claim about a policy needs that policy, frozen, on seeds that did not choose it.

Suggested experiments

Run each command from the repository root. In a git worktree, prefix each command with TOUR_VENV=~/git/spire-mentor/sts2-pycli TOUR_WEIGHTS=~/git/spire-mentor/weights.

  1. Watch the interval shrink. Run the comparison at two sizes. check.py plays both networks on the first N seeds of each panel and prints sections 1 to 4. The Wilson half-width at 200 seeds per panel is about half the half-width at 50.
  2. Cost an experiment before you run it. Close other simulations first, because the hours scale with measured throughput. Print the cost table from a short timing sample. Then use Equation \eqref{eq:mde} to compute the seed count for the effect you care about.
  3. Find the exact power of McNemar's test. Equation \eqref{eq:mde} is a normal approximation. Simulate the exact test at the measured discordance and \(n = 1{,}000\).
    1. Draw \(m \sim \operatorname{Binomial}(n, \delta_d)\).
    2. Draw \(b \sim \operatorname{Binomial}(m, (\delta_d + \Delta)/2\delta_d)\), and set \(c = m - b\).
    3. Apply mcnemar_exact(b, c) and record whether \(p \lt 0.05\).
    4. Repeat for a grid of \(\Delta\), and find the \(\Delta\) with 80% rejections.
    Compare that \(\Delta\) with the 1,000-seed row of the cost table.
  4. Regenerate this chapter's numbers. Play the 600 seeds again, then redraw every figure and number from the new data. figures.py writes data/summary.json and rewrites the figures and measured numbers in chapter.html.
