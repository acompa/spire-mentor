Reward and return

A reward is the number the environment hands the agent after each action, and the return is the sum of those numbers from one step to the end of the episode. Training tries to make the expected return as large as possible. This chapter looks at what the reward has to contain, which extra terms you can add without changing the best policy, what a discount does to an episode of about 700 decisions, and what Spire Mentor's agent is paid for.

1. A person writes the reward

A reward is a scalar the environment returns after each action. It grades how that step turned out but says nothing about which action would have been right. That is the difference from a label in supervised learning, which gives you the correct output for an example. A reward only scores the result, after the fact.

You already use rewards if you have trained a Q-network. In the target \(r_t + \gamma \max_{a'} Q(s_{t+1}, a')\), your network supplies the second term and the environment supplies \(r_t\). This chapter is about \(r_t\) and the sums built from it. Chapter 1 described the decision process that produces it.

A game does not hand out rewards on its own. Slay the Spire 2 produces facts: you reached floor 31, you beat the act-2 boss, you have 12 HP left, you did not win. Someone has to write a rule that turns some of those facts into numbers, and every later chapter optimises whatever that rule says, mistakes included.

The running example is Instinct, Spire Mentor's end-to-end agent, playing Ironclad at ascension 10. A run climbs 46 floors across three acts, takes about 650 to 700 decisions, and ends in a win or a death. Its designer fixed this reward rule before training started:

2. The return adds the rewards up

Sutton and Barto state the founding assumption of the field in one sentence and call it the reward hypothesis: any goal can be expressed as maximising the expected value of the cumulative sum of a scalar signal [1, §3.2]. It is a modelling choice, not a theorem.

The return from step \(t\) is that cumulative sum. It adds up the rewards from step \(t\) to the end of the episode and weights each one by a power of the discount \(\gamma\):

Definition 3.1 · Return
\begin{equation} G_t = \sum_{k=0}^{T-t} \gamma^{k}\, r_{t+k} \label{eq:return} \end{equation}

\(r_t\) is the reward that follows action \(a_t\), \(T\) is the last step of the episode, and \(\gamma\) lies between 0 and 1. Sutton and Barto write the same reward as \(R_{t+1}\) [1, §3.3]. This tour indexes it by the action it follows.

In the pipeline, the return comes after the reward function (Figure 3.2).

Rewards earned before step \(t\) are not part of \(G_t\), which is why the return is also called the reward-to-go. Splitting off the first term gives the recursion that every value method in Chapter 4 is built on:

\begin{equation} G_t = r_t + \gamma\, G_{t+1}, \qquad G_{T+1} = 0. \label{eq:recursion} \end{equation}

The return of a single run is random. The cards you are offered vary, so do the enemies, and during training so do the sampled actions. Training maximises the expected return under the policy, which Chapter 1 named the objective:

\begin{equation} J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\!\left[ G_0 \right]. \label{eq:objective} \end{equation}

Here \(\tau\) is one whole run, drawn by playing the policy \(\pi_\theta\) in the game. Instinct is not asked to make any one run score high, only to make the average over runs high.

Figure 3.3 adds the last piece, a value estimate \(V_\phi(s)\) that predicts the return from a state and learns by regression on observed returns. Chapter 4 covers it. Some systems, RLHF for example, also replace the hand-written reward function with a learned reward model. Instinct has no learned reward model.

One run, by hand

Take a run that reaches floors 1 through 18, beats the act-1 boss on floor 16 and dies on floor 18. With \(\gamma = 1\) its return adds three amounts:

  • 18 new floors at 0.002 each, which is 0.036.
  • One boss at 0.05, which is 0.05.
  • No win, which is 0.

So \(G_0 = 0.086\). HP at death does not change it, and neither do the elites fought or the strength of the deck.

That sum depends only on three counters read at the end of the run. Write \(F(s)\) for the highest floor reached so far, \(B(s)\) for the number of bosses paid so far, and \(W\) for 1 on a win and 0 otherwise. Each step's reward is the change in these counters:

\begin{equation} r_t = R_F\,\big[F(s_{t+1}) - F(s_t)\big] + R_B\,\big[B(s_{t+1}) - B(s_t)\big] + R_W\, W\,\mathbb{1}[t = T], \label{eq:rule} \end{equation}

with \(R_F = 0.002\), \(R_B = 0.05\) and \(R_W = 1\). When we sum Equation \eqref{eq:rule} over a run with \(\gamma = 1\), each bracket cancels against the next. Every run starts on floor 0 with no bosses paid, so only the final counters remain:

\begin{equation} G_0 = R_F\, F_T + R_B\, B_T + R_W\, W. \label{eq:return-sm} \end{equation}

Here \(F_T\) and \(B_T\) are the counters at the end. Taking the expectation splits the objective into three parts that you can read off a results table:

\begin{equation} J(\theta) = R_W \Pr_{\pi_\theta}(\text{win}) + R_B\, \mathbb{E}_{\pi_\theta}[B_T] + R_F\, \mathbb{E}_{\pi_\theta}[F_T]. \label{eq:J-decomp} \end{equation}

In other words, "maximise the return" means "maximise the win rate, with a little credit for how far the run got". The measured runs show how little.

Equation \eqref{eq:return-sm} also gives the most a losing run can score. A loss has \(W = 0\), and the best it can do is die in the last fight, against the second act-3 boss on floor 46. By then it has reached 46 floors and beaten the three bosses that pay, for a return of \(0.002 \times 46 + 0.05 \times 3 = 0.242\). The run that wins that fight scores 1.242. Some maps run two floors longer, and on those the two figures are 0.246 and 1.246.

3. Sparse reward gives the learner little to follow

A reward is sparse when almost every step pays zero and the signal arrives only at rare events, and dense when most steps carry some signal. A win-only rule for Slay the Spire is very sparse: a winning run gets one nonzero reward in about 700 steps, and a losing run gets none.

That causes two separate problems.

The learner gets no signal. If the current policy never wins, every return is zero. The policy gradient, which Chapter 5 derives, weights each action's log-probability by how much better than average the return was, roughly \((G_0 - b)\,\nabla_\theta \log \pi_\theta(a_t \mid s_t)\) for a baseline \(b\). If every return is 0 and the baseline is the average return, every weight is 0 and the gradient is exactly zero. Minsky called the long search that follows the "plateau problem" [1, §17.4]. A Q-learner has the same trouble in another form: its targets are all \(0 + \gamma \max_{a'} Q\), so nothing anchors the values.

The signal is weak and far away. Even once wins happen, the reward at step 700 has to be credited back to step 3, where a card choice made the win possible, and every step in between adds noise. Chapter 4 shows how a critic and the λ-return trade bias for variance to cope with this. A dense reward shortens the distance between a choice and some feedback about it.

Dense rewards have a cost. Each extra term is the designer's claim about what progress looks like, and the agent optimises the claim rather than the intent behind it. In Sutton and Barto's chess example, an agent rewarded for taking pieces may learn to take pieces and lose the game [1, §3.2]. The next section is about when you can add dense terms without that risk.

4. Potential-based shaping keeps the best policy

Reward shaping adds an extra term \(\tilde r_t\) to the task's reward to give the learner earlier hints. The name comes from Skinner's animal training, where the trainer rewards closer and closer approximations of a behaviour [1, §14.3, §17.4]. In general a shaping term can change which policy is best.

In 1999 Ng, Harada and Russell found the family of shaping terms that never changes the best policy [2]. Pick any function of the state, called a potential \(\Phi(s)\), and pay the discounted change in it:

Definition 3.2 · Potential-based shaping
\begin{equation} \tilde r_t = \gamma\, \Phi(s_{t+1}) - \Phi(s_t). \label{eq:pbrs} \end{equation}

\(\Phi\) can be any real-valued function of the state: a distance to a goal, a heuristic score, a guess at the value. The learner sees \(r_t + \tilde r_t\) instead of \(r_t\). This is the form that [3] quotes from Ng et al.

To see why this form is safe, we sum the shaping term along one episode from step 0, discounting step \(t\) by \(\gamma^t\) as the return does:

\begin{equation} \sum_{t=0}^{T} \gamma^{t} \tilde r_t = \sum_{t=0}^{T} \Big( \gamma^{t+1} \Phi(s_{t+1}) - \gamma^{t} \Phi(s_t) \Big) = \gamma^{T+1}\, \Phi(s_{T+1}) - \Phi(s_0). \label{eq:telescope} \end{equation}

Every potential between the first and the last appears once with a plus sign and once with a minus sign, so the sum telescopes to the discounted potential of the final state minus the potential of the start. Here \(s_{T+1}\) is the terminal state that the last action leads to. Figure 3.4 draws the cancellation for \(\gamma = 1\), with \(\Phi\) equal to 0.002 times the floor.

Adding Equation \eqref{eq:telescope} to the unshaped return gives the shaped return from the start:

\begin{equation} G'_0 = G_0 + \gamma^{T+1}\Phi(s_{T+1}) - \Phi(s_0). \label{eq:shaped-return} \end{equation}

If every terminal state has potential 0, then \(G'_0 = G_0 - \Phi(s_0)\). The start state does not depend on the policy, so the shaping shifts every policy's expected return by the same amount and the best policy stays the best. With \(\gamma = 1\), any constant shared by every terminal state works as well, because it adds the same amount to every return. Figure 3.5 adds that terminal state to Figure 3.4.

Running the same argument from any state \(s\) instead of \(s_0\) gives the value functions of the shaped problem:

\begin{equation} V'^{\pi}(s) = V^{\pi}(s) - \Phi(s), \qquad Q'^{\pi}(s, a) = Q^{\pi}(s, a) - \Phi(s). \label{eq:qshift} \end{equation}

For a Q-learner this is the clearest view. Every action in state \(s\) has its value moved by the same \(\Phi(s)\), so \(\arg\max_a Q'(s,a) = \arg\max_a Q(s,a)\). Wiewiora proved something stronger in 2003: a Q-learner that receives potential-based shaping makes the same updates as a Q-learner without shaping whose Q-table starts at \(Q_0(s,a) + \Phi(s)\) [3]. Potential-based shaping is therefore a prior on the value function, written into the reward. It changes where learning starts, not where it ends, so it can only change the speed of learning.

The argument needed two conditions, and you can apply them as a test to any reward term:

  1. Form. The term must equal \(\gamma\Phi(s_{t+1}) - \Phi(s_t)\) for a single function \(\Phi\) of the state. A term that depends on the action, or on anything outside the state, fails.
  2. Ending. With \(\gamma = 1\), every terminal state must have the same potential, and 0 is the usual choice. With \(\gamma \lt 1\) in an episodic problem, the terminal potential must be exactly 0. A shared constant \(c \ne 0\) would add \(\gamma^{T+1} c\), which depends on the episode length and so on the policy. With \(\gamma \lt 1\), an infinite horizon and a bounded \(\Phi\), the term \(\gamma^{T}\Phi\) goes to zero by itself.

The form condition also means an agent cannot farm a loop. With \(\gamma = 1\), a loop \(s \to s' \to s\) collects \(\Phi(s') - \Phi(s) + \Phi(s) - \Phi(s') = 0\) [3].

Figure 3.6 breaks the ending condition by redrawing Figure 3.5 with two endings whose potentials differ. Section 8 shows that Instinct's floor term has this shape.

5. A discount shortens the horizon

Equation \eqref{eq:return} weights a reward \(k\) steps ahead by \(\gamma^k\). You can read \(\gamma\) three ways, and in practice the third matters most.

As a preference for sooner reward. A reward now is worth more than the same reward later, as with interest. This is how Sutton and Barto introduce it: with \(\gamma = 0\) the agent cares only about the next reward, and as \(\gamma\) approaches 1 it weights the future more [1, §3.3].

As a chance of stopping. Suppose that after each step the episode is cut off with probability \(1 - \gamma\), independently. The reward at step \(k\) is collected only if the episode survives \(k\) cuts, which happens with probability \(\gamma^k\), so the expected undiscounted sum is

\begin{equation} \mathbb{E}\Big[ \sum_{k \ge 0} \mathbb{1}[\text{alive after } k \text{ steps}]\, r_{t+k} \Big] = \sum_{k \ge 0} \gamma^{k}\, r_{t+k}. \label{eq:survival} \end{equation}

Discounting is therefore the same as playing an undiscounted game with a hidden death that arrives at rate \(1-\gamma\) per step.

As a horizon. The sum of the weights says how far ahead the objective looks:

\begin{equation} \sum_{k=0}^{\infty} \gamma^{k} = \frac{1}{1-\gamma}. \label{eq:horizon} \end{equation}

This is the effective horizon: about 100 steps for \(\gamma = 0.99\) and about 1,000 for \(\gamma = 0.999\). Rewards much farther away than that barely count. Seen from the first decision of a run that wins at step \(T\), the win is worth

\begin{equation} \gamma^{T} R_W \approx e^{-T(1-\gamma)} R_W. \label{eq:discount-win} \end{equation}

The approximation uses \(\log \gamma \approx -(1-\gamma)\) for \(\gamma\) near 1. Take \(T = 678\), the median index of the last decision in the network's won runs, counted from 0 (Section 9), and \(\gamma = 0.99\). The win is then worth \(0.99^{678} \approx 0.0011\), so at the start of a run that agent would value the win below the 0.002 reward for the next floor.

Practitioners discount episodic tasks anyway, because a shorter horizon gives a less noisy return. A return that sums 700 random rewards has more variance than one that effectively sums 100, and value methods converge faster when the future shrinks. The price is bias: the agent now optimises a different objective from the one you care about. Chapter 4 shows that GAE's \(\lambda\) makes the same trade inside the advantage estimate. It biases the gradient estimate when the critic is wrong but leaves the objective unchanged, so a system can set \(\gamma = 1\) and still control variance.

6. The optimiser finds the cheapest way to score

A reward function stands in for what the designer wants, and an optimiser pushes on it until it finds the cheapest way to raise it. Sometimes that way is not the intended one. Amodei and coauthors call this reward hacking and list the ways it arises [4, §4]. Three of them apply to game agents:

  • Partially observed goals. The reward measures what the designer can see rather than the goal itself. Their example is a cleaning robot paid for not seeing messes, which learns to close its eyes.
  • Goodhart's law. A quantity that tracks the goal under normal play stops tracking it once it is optimised directly. In their words, "when a metric is used as a target, it ceases to be a good metric" [4, §4].
  • Complicated systems. The more ways an agent can act, the more likely it is that some sequence of actions exploits a gap in how the reward is computed.

For reward design this has two consequences. Every term you add is one more thing to exploit, and a sparse reward that pays only for the true goal gives the fewest. When you do add terms, prefer potential-based ones and make sure no counter can be pumped. A floor counter that paid for every floor change could be farmed by any mechanic that moves the run back and forth. A counter on the highest floor reached is a potential, and a loop earns nothing from it.

Reward hacking does not need a bug. Suppose a term pays for something that usually comes with winning, such as high HP, and the strongest play sometimes spends HP to win more often. The term then pushes the agent away from the strongest play. The agent is doing what it is paid to do, and the designer paid for the wrong thing.

7. Real systems depart from the textbook version

In the textbook version the reward is \(r(s_t, a_t, s_{t+1})\), one number per step, the return is Equation \eqref{eq:return}, and training maximises \(J\). Real systems depart from this in four ways, and Instinct shows all four.

Rewards attach to stored decisions, not to every engine step. The game engine takes many steps that the agent never sees, such as forced moves with one legal action and the end of a fight. Chapter 1 called these forced steps. Reward that arrives during them goes into a pending sum, which the environment credits to the most recent decision the agent did make. The total stays the same and only the bookkeeping moves. The implementation checks that the per-decision rewards add up to the run's total.

The reward is pre-registered. Designers often tune the reward by trial and error until the agent behaves as they want [1, §17.4], and the final result then partly reflects the designer's search. Instinct's designer fixed the rule in a pre-registration before training, together with the caps and the evaluation seeds. Chapter 8 explains why that matters.

The discount is 1 and λ controls the variance. The textbook uses \(\gamma \lt 1\) for the reasons in Section 5. Instinct keeps the objective undiscounted, so a win is worth exactly 1.0 from every decision, and it controls variance with the λ of GAE, which Chapter 4 derives.

Numerical precision bounds the smallest useful reward. The network trains in 16-bit bfloat for speed. Adjacent bfloat16 numbers are 0.0039 apart just below 1.0 and 0.0078 apart just above it, where a won state's value of about 1.24 sits. Both gaps are wider than the 0.002 floor reward, so a value head in bfloat16 could not tell one more floor from rounding error. That is why the plan keeps the value output in 32-bit floats.

8. In Spire Mentor

The training environment holds the whole reward function in three constants, and its Python version and Rust port use the same numbers.

Floors are paid against a high-water mark, the counter \(F(s)\) of Equation \eqref{eq:rule}. Reward collects in _pending_r, and _assign_pending credits it to the last stored decision. Reward that arrived before the first decision would go to unassigned_reward, which is always zero for a run from the start.

The boss bonus is paid when the agent wins a boss fight, unless that win also ends the run, so the final boss pays only the win.

AlphaDefect is another team's agent for a different character, the Defect. The plan copies its recipe and studied its checkpoints. Its argument is the one from Section 6: the stronger AlphaDefect checkpoint reached the first boss with less HP and won more often, so a term that paid for HP would have pushed against that play. The plan's table of differences from AlphaDefect gives a second reason, "no HP term (the hybrid's suspected cap [CPPO])". The evidence behind both citations is in a knowledge base that the public repository does not include, so this chapter could not check it.

The record explains less of the rest of the rule. The public repository is synced from a private one, and its commits carry no reasons. The plan and the code state some reasons and leave others open:

  • Stated. The value output stays in 32-bit floats because "bf16 spacing at V = 1 is 0.0039 > the 0.002 floor reward" (plan, line 273). The pre-registration fixes the reward rule and \(\gamma = 1\) before training. No amendment changes the reward, and Amendments 9, 11 and 12 say so explicitly.
  • Inferred. The final boss pays no boss bonus because its win already pays 1.0. The code states the rule but not the reason.
  • Inferred. The floor term continues version 1's goal that "a deeper death strictly out-scores a shallower one" (sts2-pycli/python/ppo/rewards.py, lines 7-8), at a much smaller weight. No document links the two.
  • Inferred. The reason for \(\gamma = 1\) is that it was already the default across the project's earlier PPO code. No document compares it with \(\gamma \lt 1\) for Instinct.
  • Not recorded. Why the weights are 1.0, 0.05 and 0.002, and why a capped run scores 0 like a death.

The floor and boss terms fail the ending condition

Apply the two-part test from Section 4 to the floor term, \(R_F[F(s_{t+1}) - F(s_t)]\), with the potential \(\Phi_F(s) = R_F\,F(s)\) and \(\gamma = 1\):

\begin{equation} \gamma\,\Phi_F(s_{t+1}) - \Phi_F(s_t) = R_F\,F(s_{t+1}) - R_F\,F(s_t) = R_F\big[F(s_{t+1}) - F(s_t)\big]. \label{eq:floor-form} \end{equation}

The floor term passes the form condition. It pays the change in a high-water mark, and a high-water mark is a function of the state. The boss term passes the same way with \(\Phi_B(s) = R_B\,B(s)\), and neither term can be farmed by a loop.

Both terms fail the ending condition. At the terminal state the counters keep their final values, so \(\Phi_F(s_{T+1}) = R_F F_T\), which is 0.036 for a death on floor 18 and 0.092 for a win on floor 46. The terminal potential depends on how the run went, as in Figure 3.6.

The floor term splits into a part that passes and a part that does not. We define \(\hat\Phi_F\) to equal \(\Phi_F\) everywhere except at the terminal state, where \(\hat\Phi_F = 0\). Then for every step

\begin{equation} R_F\big[F(s_{t+1}) - F(s_t)\big] = \underbrace{\hat\Phi_F(s_{t+1}) - \hat\Phi_F(s_t)}_{\text{potential-based}} \; + \; \underbrace{\mathbb{1}[t = T]\; R_F\,F_T}_{\text{terminal progress bonus}}. \label{eq:floor-split} \end{equation}

We check both cases. On a step before the last, the indicator is 0 and \(\hat\Phi_F = \Phi_F\), so the two sides agree. On the last step, the left side is \(R_F[F_T - F(s_T)]\) and the right side is \(0 - R_F F(s_T) + R_F F_T\), which is the same. By Equation \eqref{eq:telescope}, the first part sums to \(-\hat\Phi_F(s_0) = 0\) over every run. The floor term therefore changes the return only through the second part, a bonus at the end of the run proportional to how far the run got. The boss term splits the same way.

The floor and boss terms are not policy-invariant shaping. Their net effect is a terminal reward for progress, \(R_F F_T + R_B B_T\), added to the win. Equation \eqref{eq:return-sm} says the same thing, and the plan calls these terms reward, not shaping. Under them a death on floor 40 scores above a death on floor 5, which matches version 1's stated goal.

The progress bonus can therefore change which policy is best, and Equation \eqref{eq:J-decomp} says how much it takes. Write \(p\) for the win probability and \(m_L\) for the mean progress bonus of the runs the policy loses. Every win on a standard map collects the same progress, 0.242, so

\begin{equation} J = p\,(R_W + 0.242) + (1 - p)\, m_L. \label{eq:J-pm} \end{equation}

Suppose a policy gives up \(\Delta p\) of win rate. Its losses then have to collect enough extra progress \(\Delta m_L\) to pay for it, which to first order in \(\Delta p\) requires \((1-p)\,\Delta m_L \gt \Delta p\,(R_W + 0.242 - m_L)\). The exact condition replaces \(1-p\) with \(1-p+\Delta p\). With the network's measured values from Section 9, \(p = 0.81\) and \(m_L = 0.174\), giving up one percentage point of wins would need about 0.056 more progress per loss on average, or 0.053 by the exact condition. That is roughly one more boss or 28 more floors per lost run. The bonus can break a near-tie between policies, but it cannot pay for a real loss of win rate.

Version 1 used both kinds of term

Version 1 is this chapter's name for the reward of the project's earlier PPO run policy, the one Instinct replaced (README). It uses both halves of Section 4 in one design. Its return came from a potential \(\Phi = \text{base} + \text{shape}\). The base paid graded progress and the win with equal weight, \(0.5\,F/46 + 0.5\,W\) at ascension 10. The shape term was potential-based shaping on HP fraction, upgraded cards and relics, with the relic weight set to 0 by default:

The comment terminal shape = 0 meets the ending condition of Section 4, so the HP and upgrade terms were policy-invariant. The base was not, for the same reason that Instinct's floor term is not. The version-1 code also points out a stronger consequence of Equation \eqref{eq:qshift}. Let \(m\) be any function of the state. If the critic learns \(V = m - \Phi\), the shaping leaves every TD residual unchanged, so the advantages and the gradient do not depend on the shaping coefficients at all and shaping can act only through the critic's errors. Instinct has no shaping term and a smaller progress bonus.

9. What the runs show

All numbers below come from the first 300 seeds of the tour's panel A, seeds 170000000 to 170000299. Each seed was played twice, once with the published Ironclad network choosing greedily and once with uniformly random choices. The runs went through the training environment, so every reward is the reward training saw. Each run passed a three-way check: the sum of its ledger, the environment's own total, and Equation \eqref{eq:return-sm} applied to its floor, bosses and win agreed to within \(10^{-7}\).

The win came on the last decision and brought the return to 1.242, which is Equation \eqref{eq:return-sm} with \(F_T = 46\), \(B_T = 3\) and \(W = 1\).

Under the win-only rule, random play produces 300 returns of exactly zero. Under Instinct's rule the returns differ, because some random runs climb a few floors further than others, so a gradient exists. It is weak, with a standard deviation of 0.0026 against a win worth 1.0. Instinct did not start from random play. Chapter 7 covers the imitation stage that produced a policy that already wins, and that warm start is what makes a mostly sparse reward workable.

Losses end at the bosses

The largest return among the losing runs was 0.246. Won runs scored 1.242 in 238 runs and 1.246 in the other 5, which reached floor 48. All five held the Golden Compass relic, which the project's version-1 reward code notes makes the act-2 map two rows longer, so a win on that path collects 0.004 more. The losing run that scored 0.246 also reached floor 48, the last floor of a long map, so it most likely died to the final boss. The bonus is too small to matter in training, but it is a small case of Section 6: the rule pays for floors, and floors are not quite the same thing as progress.

The reward does not see HP

Among the network's won runs, the HP left at the end varied widely. The middle 80% finished with between 28% and 86% of their maximum HP, and the lowest with 10%, yet every one of them scored the same return. The rule cannot tell a win on 5 HP from a win at full health, so the objective cannot either. If the network protects HP, it does so because HP helps it win later fights. Chapter 4 makes this concrete: the critic's value estimate, not the reward, is where HP gets a price.

A discount would erase the win

The network's won runs made 679 decisions at the median, so the last decision has index 678. By Equation \eqref{eq:discount-win}, \(\gamma = 0.99\) would make the win worth 0.0011 from the first decision, and \(\gamma = 0.999\) would make it worth 0.51. An effective horizon of 100 decisions covers a fraction of one act. With \(\gamma = 1\) the win is worth 1.0 from every decision, and carrying it back through 700 steps becomes the job of the critic and λ, which Chapter 4 covers.

10. Common confusions

"The reward is the label." A label says what the right output was. A reward says how good the outcome was, after the fact, and only as one part of a sum over many steps. A run that won still contains bad decisions, and a run that died contains good ones. The policy is a classifier, but Chapter 5 trains it on a log-likelihood weighted by advantages, which come from returns, rather than on the actions as targets.

"The return of decision \(t\) is the run's return." \(G_t\) is reward-to-go and leaves out rewards that arrived before step \(t\). With \(\gamma = 1\), \(G_t = G_0 - \sum_{k \lt t} r_k\), so a choice made on floor 20 gets no credit for the floors already climbed.

"A small dense term is just shaping, so it cannot change the optimum." Only potential-based terms with a fixed terminal potential are safe. Instinct's floor term has the right form and still changes the objective, because its potential at the end depends on the run. The test is Equation \eqref{eq:shaped-return}, not the size of the term.

"γ is a property of the game." The discount is a choice in the objective. Q-learning code often treats \(\gamma = 0.99\) as a default, and in a 700-step episode that default turns a win into a rounding error at the start of the run. Instinct sets \(\gamma = 1\) and controls variance with λ.

"If HP earns nothing, the agent ignores HP." The agent ignores HP as a goal, not as a means. You have seen this in Q-learning, where \(Q(s,a)\) can be high for an action with zero immediate reward because of what the action leads to. HP is part of the state. When HP helps the agent win, states with more HP have higher value, and the policy learns to protect HP to exactly the extent that HP helps.
