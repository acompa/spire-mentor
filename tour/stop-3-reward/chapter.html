Reward and return

A reward is a number the environment gives the agent after each action. The return is the sum of those numbers from one step to the end of the episode. Training makes the expected return as large as it can. This chapter covers what the reward must contain and which extra terms leave the best policy unchanged. It then covers what a discount does to a long episode and what Spire Mentor's agent is paid for.

1. A person writes the reward

A reward is a scalar the environment returns after each action. It grades the outcome of that step. It does not say which action was right. A label in supervised learning tells you the correct output for one example. A reward only tells you how good the result was, after the fact.

You already use rewards when you train a Q-network. The target is \(r_t + \gamma \max_{a'} Q(s_{t+1}, a')\). Your network supplies the second term. The environment supplies \(r_t\). This chapter is about \(r_t\) and the sum built from it. Chapter 1 set up the decision process that produces it.

A game does not produce rewards by itself. Slay the Spire 2 produces facts. You reached floor 31. You beat the act-2 boss. You have 12 HP left. You did not win. A designer writes a rule that turns some of those facts into numbers. Every later chapter optimises whatever that rule says, including its mistakes.

The worked example is Instinct, Spire Mentor's end-to-end agent. It plays an Ironclad run at ascension 10. A run climbs 46 floors across three acts. It takes about 650 to 700 decisions and ends in a win or a death. The designer fixed this rule before training started:

2. The return adds the rewards up

Sutton and Barto state the founding assumption of the field in one sentence. They call it the reward hypothesis. Any goal can be expressed as maximising the expected value of the cumulative sum of a scalar signal [1, §3.2]. It is a modelling choice, not a theorem.

The return from step \(t\) is that cumulative sum. It adds the rewards from step \(t\) to the end of the episode, and weights each by a power of the discount \(\gamma\):

Definition 3.1 · Return
\begin{equation} G_t = \sum_{k=0}^{T-t} \gamma^{k}\, r_{t+k} \label{eq:return} \end{equation}

\(r_t\) is the reward that follows action \(a_t\). \(T\) is the last step of the episode. \(\gamma\) lies between 0 and 1. Sutton and Barto write the same reward as \(R_{t+1}\) [1, §3.3]. This tour indexes it by the action it follows.

Figure 3.2 adds the return to the pipeline.

Rewards earned before step \(t\) are not in \(G_t\). The return is a reward-to-go. Split off the first term and you get the recursion that Chapter 4 builds every value method on:

\begin{equation} G_t = r_t + \gamma\, G_{t+1}, \qquad G_{T+1} = 0. \label{eq:recursion} \end{equation}

The return of one run is a random variable. The cards you are offered vary, and so do the enemies and, during training, the sampled actions. Training maximises the expected return under the policy. Chapter 1 named this the objective:

\begin{equation} J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\!\left[ G_0 \right]. \label{eq:objective} \end{equation}

\(\tau\) is one whole run, drawn by playing the policy \(\pi_\theta\) in the game. Instinct is not asked to make one run score high. It is asked to make the average over runs score high.

Figure 3.3 adds the last part. A value estimate \(V_\phi(s)\) predicts the return from a state. It learns by regression on observed returns. Chapter 4 covers it. Some systems, such as RLHF, also replace the hand-written reward function with a learned reward model. Instinct has no learned reward model.

One run, by hand

Take a run that reaches floors 1 through 18, beats the act-1 boss on floor 16 and dies on floor 18. With \(\gamma = 1\) the return adds three amounts:

  • 18 new floors at 0.002 each, which is 0.036.
  • One boss at 0.05, which is 0.05.
  • No win, which is 0.

The return is \(G_0 = 0.086\). HP at death does not change it, and neither do the elites fought or the strength of the deck.

The sum depends only on three counters at the end of the run. Write \(F(s)\) for the highest floor reached so far, \(B(s)\) for the number of bosses paid so far, and \(W\) for 1 on a win and 0 otherwise. The rule pays the change in each counter:

\begin{equation} r_t = R_F\,\big[F(s_{t+1}) - F(s_t)\big] + R_B\,\big[B(s_{t+1}) - B(s_t)\big] + R_W\, W\,\mathbb{1}[t = T], \label{eq:rule} \end{equation}

with \(R_F = 0.002\), \(R_B = 0.05\) and \(R_W = 1\). Now we sum Equation \eqref{eq:rule} over a run with \(\gamma = 1\). Each bracket cancels against the next one. Every run starts on floor 0 with no bosses paid, so only the final counters remain:

\begin{equation} G_0 = R_F\, F_T + R_B\, B_T + R_W\, W. \label{eq:return-sm} \end{equation}

\(F_T\) and \(B_T\) are the counters at the end. Take the expectation of Equation \eqref{eq:return-sm} and the objective splits into three parts that you can read off a results table:

\begin{equation} J(\theta) = R_W \Pr_{\pi_\theta}(\text{win}) + R_B\, \mathbb{E}_{\pi_\theta}[B_T] + R_F\, \mathbb{E}_{\pi_\theta}[F_T]. \label{eq:J-decomp} \end{equation}

So "maximise the return" means "maximise the win rate, plus small credit for how far the run got". The Measured section shows how small.

Equation \eqref{eq:return-sm} also gives the largest return a losing run can have. A loss has \(W = 0\). The best it can do is die in the last fight, the second act-3 boss on floor 46. By then it has reached 46 floors and beaten three bosses that pay. Its return is \(0.002 \times 46 + 0.05 \times 3 = 0.242\). The run that wins the same fight scores 1.242. Some maps run two floors longer. On those maps the two figures are 0.246 and 1.246.

3. Sparse reward gives the learner little to follow

A reward is sparse when almost every step pays zero and the signal comes only at rare events. A reward is dense when most steps carry some signal. A win-only rule for Slay the Spire is very sparse. A winning run gets one nonzero reward in about 700 steps. A losing run gets none.

Sparse reward causes two separate problems.

The learner gets no signal. Suppose the current policy never wins. Then every return is zero. Chapter 5 derives the policy gradient. It weights each action's log-probability by how much better than average the return was, roughly \((G_0 - b)\,\nabla_\theta \log \pi_\theta(a_t \mid s_t)\) for a baseline \(b\). If every return is 0 and the baseline is the average return, every weight is 0, and the gradient is exactly zero. Minsky called the long search this causes the "plateau problem" [1, §17.4]. A Q-learner has the same trouble in another form. Its targets are all \(0 + \gamma \max_{a'} Q\), so nothing anchors the values.

The signal is weak and far away. Even when wins happen, the reward at step 700 must be credited back to step 3, where a card choice made the win possible. Every step in between adds noise. Chapter 4 shows how a critic and the λ-return trade bias for variance to deal with this. A dense reward shortens the distance between a choice and some feedback about it.

Dense rewards have a cost. Each extra term is the designer's claim about what progress looks like. The agent optimises the claim, not the intent behind it. Sutton and Barto give a chess example. An agent rewarded for taking pieces may learn to take pieces and lose the game [1, §3.2]. The next section answers when you can add dense terms without that risk.

4. Potential-based shaping keeps the best policy

Reward shaping adds an extra term \(\tilde r_t\) to the task's reward, to give the learner earlier hints. The name comes from Skinner's animal training, in which the trainer rewards closer and closer approximations of a behaviour [1, §14.3, §17.4]. In general, a shaping term can change which policy is best.

In 1999 Ng, Harada and Russell found the family of shaping terms that never changes the best policy [2]. Pick any function of the state, called a potential \(\Phi(s)\). Pay the discounted change in it:

Definition 3.2 · Potential-based shaping
\begin{equation} \tilde r_t = \gamma\, \Phi(s_{t+1}) - \Phi(s_t). \label{eq:pbrs} \end{equation}

\(\Phi\) can be any real-valued function of the state, such as a distance to a goal, a heuristic score or a guess at the value. The learner sees \(r_t + \tilde r_t\) instead of \(r_t\). This is the form that [3] quotes from Ng et al.

To see why this form is safe, we sum the shaping term along one episode from step 0. We discount step \(t\) by \(\gamma^t\), as the return does:

\begin{equation} \sum_{t=0}^{T} \gamma^{t} \tilde r_t = \sum_{t=0}^{T} \Big( \gamma^{t+1} \Phi(s_{t+1}) - \gamma^{t} \Phi(s_t) \Big) = \gamma^{T+1}\, \Phi(s_{T+1}) - \Phi(s_0). \label{eq:telescope} \end{equation}

Each potential between the first and the last appears once with a plus sign and once with a minus sign. The sum telescopes to the discounted potential of the final state minus the potential of the start. \(s_{T+1}\) is the terminal state that the last action leads to. Figure 3.4 draws the cancellation for \(\gamma = 1\), with \(\Phi\) equal to 0.002 times the floor.

Add Equation \eqref{eq:telescope} to the unshaped return. The shaped return from the start is

\begin{equation} G'_0 = G_0 + \gamma^{T+1}\Phi(s_{T+1}) - \Phi(s_0). \label{eq:shaped-return} \end{equation}

Suppose every terminal state has potential 0. Then \(G'_0 = G_0 - \Phi(s_0)\). With \(\gamma = 1\), any constant shared by every terminal state works as well, because it adds the same amount to every return. The start state does not depend on the policy. So the shaping moves every policy's expected return by the same amount, and the best policy stays the best. Figure 3.5 adds that terminal state to Figure 3.4.

The same argument works from any state \(s\) instead of \(s_0\). It gives the value functions of the shaped problem:

\begin{equation} V'^{\pi}(s) = V^{\pi}(s) - \Phi(s), \qquad Q'^{\pi}(s, a) = Q^{\pi}(s, a) - \Phi(s). \label{eq:qshift} \end{equation}

For a Q-learner this is the clearest view. Every action in state \(s\) has its value moved by the same \(\Phi(s)\), so \(\arg\max_a Q'(s,a) = \arg\max_a Q(s,a)\). Wiewiora proved a stronger result in 2003. A Q-learner that receives potential-based shaping makes the same updates as a Q-learner without shaping whose Q-table starts at \(Q_0(s,a) + \Phi(s)\) [3]. Potential-based shaping is a prior on the value function, written into the reward. It changes where learning starts, not where it ends. So it can only change the speed of learning.

Two conditions made the argument work. You can apply them as a test to any reward term:

  1. Form. The term must equal \(\gamma\Phi(s_{t+1}) - \Phi(s_t)\) for a single function \(\Phi\) of the state. A term that depends on the action fails. A term that depends on anything outside the state also fails.
  2. Ending. With \(\gamma = 1\), every terminal state must have the same potential, and 0 is the usual choice. With \(\gamma \lt 1\) in an episodic problem, the terminal potential must be exactly 0. A shared constant \(c \ne 0\) would add \(\gamma^{T+1} c\), which depends on the episode length and so on the policy. With \(\gamma \lt 1\), an infinite horizon and a bounded \(\Phi\), the term \(\gamma^{T}\Phi\) goes to zero by itself.

The form condition also stops an agent from farming a loop. A loop \(s \to s' \to s\) collects \(\Phi(s') - \Phi(s) + \Phi(s) - \Phi(s') = 0\) when \(\gamma = 1\) [3].

Figure 3.6 breaks the ending condition. It redraws Figure 3.5 with two possible endings whose potentials differ. Section 8 shows that Instinct's floor term looks like this.

5. A discount shortens the horizon

Equation \eqref{eq:return} weights a reward \(k\) steps ahead by \(\gamma^k\). There are three ways to read \(\gamma\). In practice the third matters most.

As a preference for sooner reward. A reward now is worth more than the same reward later, as with interest. Sutton and Barto introduce it this way. With \(\gamma = 0\) the agent cares only about the next reward. As \(\gamma\) approaches 1, the agent weights the future more [1, §3.3].

As a chance of stopping. Suppose that after each step the episode is cut off with probability \(1 - \gamma\), independently. The reward at step \(k\) is collected only if the episode survives \(k\) cuts. That happens with probability \(\gamma^k\). The expected undiscounted sum is then

\begin{equation} \mathbb{E}\Big[ \sum_{k \ge 0} \mathbb{1}[\text{alive after } k \text{ steps}]\, r_{t+k} \Big] = \sum_{k \ge 0} \gamma^{k}\, r_{t+k}. \label{eq:survival} \end{equation}

Discounting is the same as playing an undiscounted game with a hidden death that arrives at rate \(1-\gamma\) per step.

As a horizon. The sum of the weights tells you how far ahead the objective looks:

\begin{equation} \sum_{k=0}^{\infty} \gamma^{k} = \frac{1}{1-\gamma}. \label{eq:horizon} \end{equation}

This is the effective horizon. With \(\gamma = 0.99\) it is about 100 steps. With \(\gamma = 0.999\) it is about 1,000. Rewards much farther away than the horizon barely count. Seen from the first decision of a run that wins at step \(T\), the win is worth

\begin{equation} \gamma^{T} R_W \approx e^{-T(1-\gamma)} R_W. \label{eq:discount-win} \end{equation}

The approximation uses \(\log \gamma \approx -(1-\gamma)\) for \(\gamma\) near 1. Take \(T = 678\), the median index of the last decision in the network's won runs, counted from 0 (Section 9), and \(\gamma = 0.99\). The win is then worth \(0.99^{678} \approx 0.0011\). At the start of a run, that agent would value the win less than the 0.002 reward for the next floor.

Practitioners discount episodic tasks anyway because a shorter horizon gives a less noisy return. A return that sums 700 random rewards has more variance than one that effectively sums 100. Value methods also converge faster when the future shrinks. The price is bias. The agent now optimises a different objective from the one you care about. Chapter 4 shows that GAE's \(\lambda\) makes the same trade inside the advantage estimate. It biases the gradient estimate when the critic is wrong, but it leaves the objective unchanged. So a system can set \(\gamma = 1\) and still control variance.

6. The optimiser finds the cheapest way to score

A reward function stands in for what the designer wants. An optimiser pushes on it until it finds the cheapest way to raise it. Sometimes that way is not the intended one. Amodei and coauthors call this reward hacking and list the ways it arises [4, §4]. Three of them apply to game agents:

  • Partially observed goals. The reward measures what the designer can see, not the goal itself. Their example is a cleaning robot paid for not seeing messes. It learns to close its eyes.
  • Goodhart's law. A quantity that tracks the goal under normal play stops tracking it once it is optimised directly. In their words, "when a metric is used as a target, it ceases to be a good metric" [4, §4].
  • Complicated systems. The more ways the agent can act, the more likely some sequence exploits a gap in how the reward is computed.

For reward design, this has two consequences. First, every term you add is one more thing to exploit. A sparse reward that pays only for the true goal gives the fewest. Second, when you add terms, prefer potential-based ones, and make sure no counter can be pumped. A floor counter that paid for every floor change could be farmed by any mechanic that moves the run back and forth. A counter on the highest floor reached is a potential, and a loop earns nothing from it.

A subtler case needs no bug. Suppose a term pays for something that usually comes with winning, such as high HP. Suppose also that the strongest play sometimes spends HP to win more often. The term then pushes the agent away from the strongest play. The agent is not cheating. It does what it is paid to do, and the designer paid for the wrong thing.

7. Real systems bend the textbook version

The textbook version is simple. The reward is \(r(s_t, a_t, s_{t+1})\), one number per step. The return is Equation \eqref{eq:return}. Training maximises \(J\). Real systems depart from it in four ways, and Instinct shows all four.

Rewards attach to stored decisions, not to every engine step. The game engine takes many steps that the agent never sees, such as forced moves with one legal action and the end of a fight. Chapter 1 called these forced steps. Reward that arrives during them goes into a pending sum. The environment credits the pending sum to the most recent decision that the agent did make. The total does not change. Only the bookkeeping moves. The implementation checks that the per-decision rewards add up to the run's total.

The reward is pre-registered. In research practice designers often tune the reward by trial and error until the agent behaves as they want [1, §17.4]. The final result then partly reflects the designer's search. Instinct's designer fixed the rule in a pre-registration before training, together with the caps and the evaluation seeds. Chapter 8 explains why that matters.

The discount is 1 and λ controls the variance. The textbook uses \(\gamma \lt 1\) for the reasons in Section 5. Instinct keeps the objective undiscounted, so a win is worth exactly 1.0 from every decision. It controls variance with the λ of GAE, which Chapter 4 derives.

Numerical precision bounds the smallest useful reward. The network trains in 16-bit bfloat for speed. Adjacent bfloat16 numbers are 0.0039 apart just below 1.0 and 0.0078 apart just above it, where a won state's value of about 1.24 sits. Both gaps are wider than the 0.002 floor reward. A value head in bfloat16 could not tell one more floor from rounding error. The plan keeps the value output in 32-bit floats for this reason.

8. In Spire Mentor

The training environment holds the whole reward function in three constants. Its Python version and its Rust port use the same numbers.

The environment pays floors against a high-water mark, the counter \(F(s)\) of Equation \eqref{eq:rule}. Reward collects in _pending_r, and _assign_pending credits it to the last stored decision. Reward before the first decision would go to unassigned_reward. For a run from the start, that bucket is always zero.

The environment pays the boss bonus when the agent wins a boss fight, unless that win also ends the run. The final boss pays only the win.

The plan states the rule and gives one reason for what it leaves out:

AlphaDefect is another team's agent for a different character, the Defect. The plan copies its recipe and studied its checkpoints. The plan's argument is the one from Section 6. The stronger AlphaDefect checkpoint reached the first boss with less HP and won more often. A term that paid for HP would have pushed against that play. The plan gives a second reason in its table of differences from AlphaDefect: "no HP term (the hybrid's suspected cap [CPPO])". The evidence behind both citations sits in a knowledge base that the public repository does not include. This chapter could not check it.

The record explains less of the rest of the rule. The public repository is synced from a private one, and its commits carry no reasons. Here is what the plan and code say, and what they leave open:

  • Stated. The value output stays in 32-bit floats because "bf16 spacing at V = 1 is 0.0039 > the 0.002 floor reward" (plan, line 273). The pre-registration fixes the reward rule and \(\gamma = 1\) before training. No amendment changes the reward, and Amendments 9, 11 and 12 say so explicitly.
  • Inferred. The final boss pays no boss bonus because its win already pays 1.0. The code states the rule but not the reason.
  • Inferred. The floor term continues version 1's goal that "a deeper death strictly out-scores a shallower one" (sts2-pycli/python/ppo/rewards.py, lines 7-8), at a much smaller weight. No document links the two.
  • Inferred. The reason for \(\gamma = 1\). It was already the default across the project's earlier PPO code. No document compares it with \(\gamma \lt 1\) for Instinct.
  • Not recorded. Why the weights are 1.0, 0.05 and 0.002, and why a capped run scores 0 like a death.

The floor and boss terms fail the ending condition

Apply the two-part test from Section 4. Take the floor term, \(R_F[F(s_{t+1}) - F(s_t)]\). Try the potential \(\Phi_F(s) = R_F\,F(s)\) with \(\gamma = 1\):

\begin{equation} \gamma\,\Phi_F(s_{t+1}) - \Phi_F(s_t) = R_F\,F(s_{t+1}) - R_F\,F(s_t) = R_F\big[F(s_{t+1}) - F(s_t)\big]. \label{eq:floor-form} \end{equation}

The floor term passes the form condition. It pays the change in a high-water mark, and a high-water mark is a function of the state. The boss term passes the same way with \(\Phi_B(s) = R_B\,B(s)\). Neither term can be farmed by a loop.

Both terms fail the ending condition. At the terminal state the counters keep their final values. So \(\Phi_F(s_{T+1}) = R_F F_T\). That is 0.036 for a death on floor 18 and 0.092 for a win on floor 46. The terminal potential depends on how the run went. This is the case in Figure 3.6.

The floor term splits into a part that passes and a part that does not. We define \(\hat\Phi_F\) to equal \(\Phi_F\) everywhere except at the terminal state, where \(\hat\Phi_F = 0\). Then for every step

\begin{equation} R_F\big[F(s_{t+1}) - F(s_t)\big] = \underbrace{\hat\Phi_F(s_{t+1}) - \hat\Phi_F(s_t)}_{\text{potential-based}} \; + \; \underbrace{\mathbb{1}[t = T]\; R_F\,F_T}_{\text{terminal progress bonus}}. \label{eq:floor-split} \end{equation}

We check both cases. On a step before the last, the indicator is 0 and \(\hat\Phi_F = \Phi_F\), so the two sides agree. On the last step, the left side is \(R_F[F_T - F(s_T)]\). The right side is \(0 - R_F F(s_T) + R_F F_T\), which is the same. By Equation \eqref{eq:telescope}, the first part sums to \(-\hat\Phi_F(s_0) = 0\) over every run. So the floor term changes the return only through the second part. That part is a bonus at the end of the run, proportional to how far the run got. The boss term splits the same way.

The floor and boss terms are not policy-invariant shaping. Their net effect is a terminal reward for progress, \(R_F F_T + R_B B_T\), added to the win. That is Equation \eqref{eq:return-sm} read another way. The plan calls these terms reward, not shaping. The result is that a death on floor 40 scores above a death on floor 5, which matches version 1's stated goal.

The progress bonus can change which policy is best. Equation \eqref{eq:J-decomp} says how much it takes. Write \(p\) for the win probability and \(m_L\) for the mean progress bonus of the runs the policy loses. Every win on a standard map collects the same progress, 0.242. So

\begin{equation} J = p\,(R_W + 0.242) + (1 - p)\, m_L. \label{eq:J-pm} \end{equation}

Suppose a policy gives up \(\Delta p\) of win rate. Its losses must collect enough extra progress \(\Delta m_L\) to pay for it. To first order in \(\Delta p\), that requires \((1-p)\,\Delta m_L \gt \Delta p\,(R_W + 0.242 - m_L)\). The exact condition replaces \(1-p\) with \(1-p+\Delta p\). Use the network's measured values from Section 9, \(p = 0.81\) and \(m_L = 0.174\). To give up one percentage point of wins, the losses would need about 0.056 more progress on average, or 0.053 by the exact condition. That is roughly one more boss or 28 more floors per lost run. The bonus can break a near-tie. It cannot buy a real loss of win rate.

Version 1 used both kinds of term

The project's earlier PPO run policy, the one Instinct replaced (README), used a different reward. This chapter calls it version 1. It shows both halves of Section 4 in one design. Its return came from a potential \(\Phi = \text{base} + \text{shape}\). The base paid graded progress and the win with equal weight, \(0.5\,F/46 + 0.5\,W\) at ascension 10. The shape term was potential-based shaping on HP fraction, upgraded cards and relics, with the relic weight set to 0 by default:

The comment terminal shape = 0 meets the ending condition of Section 4. So the HP and upgrade terms were policy-invariant. The base was not, for the same reason that Instinct's floor term is not. The version-1 code also notes a stronger consequence of Equation \eqref{eq:qshift}. Let \(m\) be any function of the state. If the critic learns \(V = m - \Phi\), the shaping leaves every TD residual unchanged. Then the advantages and the gradient do not depend on the shaping coefficients at all. Shaping could act only through the critic's errors. Instinct has no shaping term and a smaller progress bonus.

Under the win-only rule, random play produces 300 returns of exactly zero. Under Instinct's rule the returns differ, because some random runs climb a few floors further than others. So a gradient exists. It is weak, with a standard deviation of 0.0026 against a win worth 1.0. Instinct did not start from random play. Chapter 7 covers the imitation stage that produced a policy that already wins. That warm start is what makes a mostly sparse reward workable.

Losses end at the bosses

The largest return among the losing runs was 0.246. Won runs scored 1.242 in 238 runs and 1.246 in 5 runs. The 1.246 runs reached floor 48. All five held the Golden Compass relic. The project's version-1 reward code notes that this relic makes the act-2 map two rows longer. So a win on that path collects 0.004 more. The losing run that scored 0.246 also reached floor 48, the last floor of a long map, so it most likely died to the final boss. The bonus is too small to matter in training. It is still a small case of Section 6. The rule pays for floors, and floors are not quite the same thing as progress.

The reward does not see HP

Among the network's won runs, the HP left at the end varied widely. The middle 80% finished with between 28% and 86% of their maximum HP. The lowest finished with 10%. Every one of them scored the same return. The rule cannot tell a win on 5 HP from a win at full health, so the objective cannot either. If the network protects HP, it does so because HP helps it win later fights. Chapter 4 makes this concrete. The critic's value estimate, not the reward, is where HP gets a price.

A discount would erase the win

The network's won runs made 679 decisions at the median, so the last decision has index 678. By Equation \eqref{eq:discount-win}, \(\gamma = 0.99\) would make the win worth 0.0011 from the first decision. \(\gamma = 0.999\) would make it worth 0.51. An effective horizon of 100 decisions covers a fraction of one act. With \(\gamma = 1\) the win is worth 1.0 from every decision. Carrying it back through 700 steps becomes the job of the critic and λ. Chapter 4 covers both.

10. Common confusions

"The reward is the label." A label says what the right output was. A reward says how good the outcome was, after the fact, and only as part of a sum over many steps. A run that won still contains bad decisions. A run that died contains good ones. The policy is a classifier, but Chapter 5 trains it on a log-likelihood weighted by advantages, which come from returns, not on the actions as targets.

"The return of decision \(t\) is the run's return." \(G_t\) is reward-to-go. It leaves out rewards that arrived before step \(t\). With \(\gamma = 1\), \(G_t = G_0 - \sum_{k \lt t} r_k\). A choice made on floor 20 gets no credit for the floors already climbed.

"A small dense term is just shaping, so it cannot change the optimum." Only potential-based terms with a fixed terminal potential are safe. Instinct's floor term has the right form and still changes the objective, because its potential at the end depends on the run. Size is not the test. Equation \eqref{eq:shaped-return} is.

"γ is a property of the game." The discount is a choice in the objective. Q-learning code often treats \(\gamma = 0.99\) as a default. In a 700-step episode, that default turns a win into a rounding error at the start of the run. Instinct sets \(\gamma = 1\) and controls variance with λ.

"If HP earns nothing, the agent ignores HP." The agent ignores HP as a goal, not as a means. You know this pattern from Q-learning. \(Q(s,a)\) can be high for an action with zero immediate reward because of what the action leads to. HP is part of the state. When HP helps the agent win, states with more HP have higher value. The policy learns to protect HP to exactly the extent that HP helps.

11. Run the experiments

Run every command from the root of a tour worktree. Before the first command, set the simulator's environment in your shell:

  1. Print a reward ledger and the panel breakdown. Run check.py. With --quick it plays 24 seeds per policy instead of 300. You see one run's ledger, the mean return of each policy split by term, and the scores of three hypothetical runs.

  2. Rescore the saved runs under other rules. Run figures.py rescore with a discount of your choice. It prints the mean return under the win-only rule, the floors-only rule and the full rule, and the discounted returns of the three saved ledgers. Compare the result for 0.99 and 0.9999 with Figure 3.10.

  3. Regenerate the data and the figures. Run collect to replay both policies on 300 seeds and rewrite chapter_data.json. Then run render to redraw Figures 3.7 to 3.10 inside this page.

  4. Check the bookkeeping. Run the stop's tests. They play real runs and assert that the ledger, the environment's total and Equation \eqref{eq:return-sm} agree.
